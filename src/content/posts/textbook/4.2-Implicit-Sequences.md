## 4.2   隐式序列

一个序列可以被*表示*出来，而无需把其中每个元素都显式地*存储*在计算机内存中。也就是说，我们可以构造这样一个对象：它能提供对某个顺序数据集中所有元素的访问，却不必事先计算出所有这些元素并把它们存起来。相反，我们按需计算元素。

这一思想的一个简单例子出现在第 2 章引入的 `range` 序列类型中。一个 `range` 表示一段连续、有界的整数序列。然而，情况并非是该序列的每个元素都在内存中被显式表示。相反，当我们向一个 `range` 请求某个元素时，它才被计算出来。因此，我们可以表示非常大的整数区间而不必占用大块内存。区间对象中仅仅存储了区间的端点。

```python
>>> r = range(10000, 1000000000)
>>> r[45006230]
45016230
```

在这个例子中，当 range 实例被构造时，该区间中的 999,990,000 个整数并没有全部被存储。相反，range 对象把第一个元素 10,000 加到索引 45,006,230 上，从而得到元素 45,016,230。按需计算值，而不是从已有的表示中取出它们，是*惰性*计算的一个例子。在计算机科学中，*惰性计算*描述的是任何把某个值的计算推迟到该值真正需要时才进行的程序。

**迭代器（iterator）**是这样一种对象：它提供对某个底层顺序数据集的顺序访问。迭代器是许多编程语言（包括 Python）中的内置对象。迭代器抽象包含两个组成部分：一种用于取出某个底层元素序列中*下一个*元素的机制，以及一种用于表明该序列已到达末尾、没有更多元素剩余的机制。在具有内置对象系统的编程语言中，这种抽象通常对应一个可以由类实现的特定接口。Python 中迭代器的接口将在下一节描述。

迭代器的用处源自这样一个事实：某个迭代器所对应的底层数据序列可能并没有在内存中被显式表示。迭代器提供了一种机制，用来依次考察一系列值中的每一个，但所有这些元素并不需要同时被存储。相反，当我们向迭代器请求下一个元素时，该元素可能是按需计算出来的，而不是从已有的内存来源中取出的。

range 之所以能够惰性地计算序列的元素，是因为它表示的序列是均匀的，并且任何一个元素都很容易从区间的起止边界算出。迭代器允许对更广泛的一类底层顺序数据集进行惰性生成，因为它们不需要提供对底层序列中任意元素的访问。相反，它们只需在每次请求另一个元素时，按顺序计算出序列中的下一个元素。虽然这不如访问序列的任意元素（称为*随机访问*）那样灵活，但对于数据处理应用而言，对顺序数据序列的*顺序访问*往往已经足够。

### 4.2.1   迭代器

Python 迭代器接口包含两条消息。`__next__` 消息向迭代器查询它所表示的底层序列中的下一个元素。作为对以方法形式调用 `__next__` 的响应，迭代器可以执行任意计算，以便取出或算出底层序列中的下一个元素。对 `__next__` 的调用会对迭代器做出改动性的变更：它们推进迭代器的位置。因此，多次调用 `__next__` 将返回底层序列中依次排列的元素。Python 通过在调用 `__next__` 期间引发 `StopIteration` 异常，来表明底层序列已到达末尾。

下面的 `LetterIter` 类迭代一个底层字母序列，从某个 `start` 字母开始，直到但不包括某个 `end` 字母。实例属性 `next_letter` 存储下一个将要返回的字母。`__next__` 方法返回该字母，并用它计算出新的 `next_letter`。

```python
>>> class LetterIter:
        """An iterator over letters of the alphabet in ASCII order."""
        def __init__(self, start='a', end='e'):
            self.next_letter = start
            self.end = end
        def __next__(self):
            if self.next_letter == self.end:
                raise StopIteration
            letter = self.next_letter
            self.next_letter = chr(ord(letter)+1)
            return letter
```

使用这个类，我们可以通过 `__next__` 方法或内置的 `next` 函数（它会对自己的参数调用 `__next__`）来顺序访问字母。

```python
>>> letter_iter = LetterIter()
>>> letter_iter.__next__()
'a'
>>> letter_iter.__next__()
'b'
>>> next(letter_iter)
'c'
>>> letter_iter.__next__()
'd'
>>> letter_iter.__next__()
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "<stdin>", line 12, in next
StopIteration
```

迭代器是可变的：它们在推进的过程中跟踪自己在某个底层值序列中的位置。当到达末尾时，迭代器就被用尽了。一个 `LetterIter` 实例只能被迭代一次。在其 `__next__()` 方法引发 `StopIteration` 异常之后，从此以后它都会继续如此。通常，迭代器不会被重置；相反，我们会创建一个新实例来开始一次新的迭代。

迭代器还允许我们通过实现一个永不引发 `StopIteration` 异常的 `__next__` 方法来表示无穷序列。例如，下面的 `Positives` 类迭代正整数的无穷序列。Python 中的内置 `next` 函数会对自己的参数调用 `__next__` 方法。

```python
>>> class Positives:
        def __init__(self):
            self.next_positive = 1;
        def __next__(self):
            result = self.next_positive
            self.next_positive += 1
            return result
>>> p = Positives()
>>> next(p)
1
>>> next(p)
2
>>> next(p)
3
```

### 4.2.2   可迭代对象

如果当一个对象的 `__iter__` 方法被调用时，它返回一个迭代器，那么这个对象就是可迭代的。可迭代值表示数据集合，它们提供一种固定的表示，并且可以产生一个以上的迭代器。

例如，下面 `Letters` 类的实例表示一连串连续的字母。每当它的 `__iter__` 方法被调用时，就会构造一个新的 `LetterIter` 实例，从而允许对该序列的内容进行顺序访问。

```python
>>> class Letters:
        def __init__(self, start='a', end='e'):
            self.start = start
            self.end = end
        def __iter__(self):
            return LetterIter(self.start, self.end)
```

内置的 `iter` 函数会对自己的参数调用 `__iter__` 方法。在下面的一系列表达式中，来自同一个可迭代序列的两个迭代器各自独立地依次产生字母。

```python
>>> b_to_k = Letters('b', 'k')
>>> first_iterator = b_to_k.__iter__()
>>> next(first_iterator)
'b'
>>> next(first_iterator)
'c'
>>> second_iterator = iter(b_to_k)
>>> second_iterator.__next__()
'b'
>>> first_iterator.__next__()
'd'
>>> first_iterator.__next__()
'e'
>>> second_iterator.__next__()
'c'
>>> second_iterator.__next__()
'd'
```

可迭代的 `Letters` 实例 `b_to_k` 与 `LetterIter` 迭代器实例 `first_iterator` 和 `second_iterator` 的不同之处在于：`Letters` 实例不发生变化，而迭代器实例在每次调用 `next`（或等价地，每次调用 `__next__`）时都会变化。迭代器跟踪在顺序数据中的进展，而可迭代对象表示的则是数据本身。

### 4.2.3   For 语句

Python 中的 `for` 语句作用于迭代器。如果对象拥有一个返回*迭代器*的 `__iter__` 方法，那么它就是*可迭代的*（一种接口）。可迭代对象可以作为 `for` 语句头部中 `<expression>` 的值：

```python
for <name> in <expression>:
    <suite>
```

为执行一条 `for` 语句，Python 会对头部的 `<expression>` 求值，它必须产生一个可迭代的值。然后，会在该值上调用 `__iter__` 方法。在引发 `StopIteration` 异常之前，Python 反复调用那个迭代器上的 `__next__` 方法，并把结果绑定到 `for` 语句中的 `<name>`。随后，它执行 `<suite>`。

```python
>>> counts = [1, 2, 3]
>>> for item in counts:
        print(item)
1
2
3
```

在上面的例子中，`counts` 列表通过其 `__iter__()` 方法返回一个迭代器。`for` 语句随后反复调用该迭代器的 `__next__()` 方法，并在每次调用时把返回的值赋给 `item`。这一过程持续进行，直到迭代器引发 `StopIteration` 异常，此时 `for` 语句的执行便结束了。

借助我们对迭代器的了解，我们可以用 `while`、赋值和 `try` 语句来实现 `for` 语句的执行规则。

```python
>>> items = counts.__iter__()
>>> try:
        while True:
            item = items.__next__()
            print(item)
    except StopIteration:
        pass
1
2
3
```

在上面，通过调用 `counts` 的 `__iter__` 方法返回的迭代器被绑定到名字 `items`，以便可以依次向它查询每个元素。`StopIteration` 异常的处理子句什么也不做，但处理该异常提供了一种退出 `while` 循环的控制机制。

要在 for 循环中使用一个迭代器，该迭代器还必须拥有一个 `__iter__` 方法。Python 文档的
*Iterator types <http://docs.python.org/3/library/stdtypes.html#iterator-types>
`_ 一节建议，迭代器应当拥有一个返回迭代器本身 `__iter__`*
方法，这样所有的迭代器就都是可迭代的。

### 4.2.4   生成器与 Yield 语句

上面的 `Letters` 和 `Positives` 对象要求我们向对象中引入一个新字段 `self.current`，以跟踪在序列中的进展。对于像上面所示那样简单的序列，这很容易做到。然而，对于复杂的序列，`__next__` 方法可能很难保存它在计算中的位置。生成器允许我们借助 Python 解释器的特性来定义更复杂的迭代。

**生成器（generator）**是由一类称为*生成器函数*的特殊函数返回的迭代器。生成器函数与常规函数的不同之处在于：它们不是在函数体中使用 `return` 语句，而是使用 `yield` 语句来返回系列中的元素。

生成器不使用对象的属性来跟踪它们在某个系列中的进展。相反，它们控制生成器函数的执行：每当生成器的 `__next__` 方法被调用时，生成器函数就运行到下一个 `yield` 语句被执行之处。`Letters` 迭代器可以用一个生成器函数更紧凑地实现。

```python
>>> def letters_generator():
        current = 'a'
        while current <= 'd':
            yield current
            current = chr(ord(current)+1)
```

```python
>>> for letter in letters_generator():
        print(letter)
a
b
c
d
```

尽管我们从未显式定义 `__iter__` 或 `__next__` 方法，`yield` 语句表明我们正在定义一个生成器函数。当被调用时，生成器函数并不返回某个特定的产出值，而是返回一个 `generator`（它是一种迭代器），它自身可以返回那些产出的值。生成器对象拥有 `__iter__` 和 `__next__` 方法，并且每次调用 `__next__` 都会让生成器函数从上一次停下的地方继续执行，直到另一个 `yield` 语句被执行。

第一次调用 `__next__` 时，程序从 `letters_generator` 函数体开始执行语句，直到遇到 `yield` 语句。然后，它暂停并返回 `current` 的值。`yield` 语句不会销毁新创建的环境，而是把它保存下来以供之后使用。当再次调用 `__next__` 时，执行从它上次停下的地方恢复。`current` 以及 `letters_generator` 作用域中任何其他被绑定名字的值，都会在后续对 `__next__` 的调用中得以保留。

我们可以通过手动调用 `____next__()` 来逐步走过这个生成器：

```python
>>> letters = letters_generator()
>>> type(letters)
<class 'generator'>
>>> letters.__next__()
'a'
>>> letters.__next__()
'b'
>>> letters.__next__()
'c'
>>> letters.__next__()
'd'
>>> letters.__next__()
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
StopIteration
```

生成器在第一次调用 `__next__` 之前不会开始执行其生成器函数的任何函数体语句。每当其生成器函数返回时，生成器就会引发 `StopIteration` 异常。

### 4.2.5   用 Yield 创建可迭代对象

在 Python 中，迭代器只对底层系列的元素做一次遍历。在那次遍历之后，当调用 `__next__` 时，迭代器将继续引发 `StopIteration` 异常。许多应用需要对元素进行多次迭代。例如，为了枚举元素的所有对，我们必须对列表迭代多次。

```python
>>> def all_pairs(s):
        for item1 in s:
            for item2 in s:
                yield (item1, item2)
```

```python
>>> list(all_pairs([1, 2, 3]))
[(1, 1), (1, 2), (1, 3), (2, 1), (2, 2), (2, 3), (3, 1), (3, 2), (3, 3)]
```

序列本身并不是迭代器，而是*可迭代*对象。Python 中的可迭代接口由一条消息组成，即 `__iter__`，它返回一个迭代器。Python 中的内置序列类型在其 `__iter__` 方法被调用时，会返回新的迭代器实例。如果一个可迭代对象在每次调用 `__iter__` 时都返回一个全新的迭代器实例，那么它就可以被迭代多次。

通过实现可迭代接口，我们可以定义新的可迭代类。例如，下面这个*可迭代的* `LettersWithYield` 类在每次调用 `__iter__` 时都返回一个对字母的全新迭代器。

```python
>>> class LettersWithYield:
        def __init__(self, start='a', end='e'):
            self.start = start
            self.end = end
        def __iter__(self):
            next_letter = self.start
            while next_letter < self.end:
                yield next_letter
                next_letter = chr(ord(next_letter)+1)
```

`__iter__` 方法是一个生成器函数；它返回一个生成器对象，该对象产出从 `'a'` 到 `'d'` 的字母，然后停止。每次我们调用这个方法，都会有一个新的生成器开始对顺序数据进行一次全新的遍历。

```python
>>> letters = LettersWithYield()
>>> list(all_pairs(letters))[:5]
[('a', 'a'), ('a', 'b'), ('a', 'c'), ('a', 'd'), ('b', 'a')]
```

### 4.2.6   流

*流（stream）*提供了另一种隐式地表示顺序数据的方式。一个流就是一个惰性计算的递归列表。与第 2 章中的 `Rlist` 类一样，一个 `Stream` 实例会响应获取其 `first` 元素和流的 `rest` 的请求。与 `Rlist` 一样，一个 `Stream` 的 `rest` 本身也是一个 `Stream`。与 `Rlist` 不同的是，流的 `rest` 只有在被查找时才计算，而不是事先存储起来。也就是说，流的 `rest` 是惰性计算的。

为了实现这种惰性求值（lazy evaluation），流存储了一个用于计算流的 rest 的函数。每当这个函数被调用时，其返回值都会作为流的一部分，被缓存在一个名为 `_rest` 的属性中；该属性名字中的下划线表示不应当直接访问它。

可访问的属性 `rest` 是一个 property 方法，它返回流的 rest，并在必要时计算它。有了这种设计，流存储的是*如何计算*流的 rest，而不是总是显式地存储 rest。

```python
>>> class Stream:
        """A lazily computed recursive list."""
        class empty(object):
            def __repr__(self):
                return 'Stream.empty'
        empty = empty()
        def __init__(self, first, compute_rest=lambda: empty):
            assert callable(compute_rest), 'compute_rest must be callable.'
            self.first = first
            self._compute_rest = compute_rest
        @property
        def rest(self):
            """Return the rest of the stream, computing it if necessary."""
            if self._compute_rest is not None:
                self._rest = self._compute_rest()
                self._compute_rest = None
            return self._rest
        def __repr__(self):
            return 'Stream({0}, <...>)'.format(repr(self.first))
```

递归列表是用嵌套表达式定义的。例如，我们可以像下面这样创建一个表示元素 1 然后 5 的 `Rlist`：

```python
>>> r = Rlist(1, Rlist(2+3, Rlist(9)))
```

同样，我们也可以创建一个表示同一系列的 `Stream`。在流的 rest 被请求之前，`Stream` 实际上并不会计算第二个元素 5。我们通过创建匿名函数来实现这一效果。

```python
>>> s = Stream(1, lambda: Stream(2+3, lambda: Stream(9)))
```

这里，1 是流的第一个元素，而紧随其后的 `lambda` 表达式返回一个用于计算流 rest 的函数。

访问递归列表 `r` 和流 `s` 的元素的过程是相似的。然而，5 是存储在 `r` 中的，而对于 `s`，它是在第一次被请求时经由加法按需计算出来的。

```python
>>> r.first
1
>>> s.first
1
>>> r.rest.first
5
>>> s.rest.first
5
>>> r.rest
Rlist(5, Rlist(9))
>>> s.rest
Stream(5, <...>)
```

虽然 `r` 的 `rest` 是一个两元素的递归列表，但 `s` 的 `rest` 中包含了一个用于计算 rest 的函数；它将会返回空流这一事实，可能至今还未被发现。

当一个 `Stream` 实例被构造时，字段 `self._rest` 为 `None`，表示该 `Stream` 的 rest 尚未被计算。当通过点表达式请求 `rest` 属性时，`rest` property 方法被调用，它通过 `self._rest = self._compute_rest()` 触发计算。由于 `Stream` 内部的缓存机制，`compute_rest` 函数只会被调用一次，随后便被丢弃。

`compute_rest` 函数的本质属性是：它不接收任何参数，并且返回一个 `Stream` 或 `Stream.empty`。

惰性求值使我们能够用流来表示无穷的顺序数据集。例如，我们可以表示从任意 `first` 值开始的递增整数。

```python
>>> def integer_stream(first):
        def compute_rest():
            return integer_stream(first+1)
        return Stream(first, compute_rest)
```

```python
>>> positives = integer_stream(1)
>>> positives
Stream(1, <...>)
>>> positives.first
1
```

当 `integer_stream` 第一次被调用时，它返回一个流，其 `first` 是序列中的第一个整数。然而，`integer_stream` 实际上是递归的，因为这个流的 `compute_rest` 会以一个递增后的参数再次调用 `integer_stream`。我们说 `integer_stream` 是惰性的，因为对 `integer_stream` 的递归调用只有在某个整数流的 `rest` 被请求时才会进行。

```python
>>> positives.first
1
>>> positives.rest.first
2
>>> positives.rest.rest
Stream(3, <...>)
```

那些用于操纵序列的高阶函数——`map` 和 `filter`——同样适用于流，尽管它们的实现必须改变，以惰性地应用其参数函数。函数 `map_stream` 把一个函数映射到一个流上，从而产生一个新的流。局部定义的 `compute_rest` 函数确保：每当 rest 被计算时，该函数都会被映射到流的 rest 上。

```python
>>> def map_stream(fn, s):
        if s is Stream.empty:
            return s
        def compute_rest():
            return map_stream(fn, s.rest)
        return Stream(fn(s.first), compute_rest)
```

一个流可以通过定义一个 `compute_rest` 函数来过滤，该函数把过滤函数应用到流的 rest 上。如果过滤函数拒绝流的第一个元素，那么 rest 会立即被计算。因为 `filter_stream` 是递归的，所以在找到一个有效的 `first` 元素之前，rest 可能会被计算多次。

```python
>>> def filter_stream(fn, s):
        if s is Stream.empty:
            return s
        def compute_rest():
            return filter_stream(fn, s.rest)
        if fn(s.first):
            return Stream(s.first, compute_rest)
        else:
            return compute_rest()
```

`map_stream` 和 `filter_stream` 这两个函数展示了流处理中的一个常见模式：一个局部定义的 `compute_rest` 函数在每次 rest 被计算时，递归地把某个处理函数应用到流的 rest 上。

为了查看流的内容，我们可以把最多前 `k` 个元素强制转换为一个 Python `list`。

```python
>>> def first_k_as_list(s, k):
        first_k = []
        while s is not Stream.empty and k > 0:
            first_k.append(s.first)
            s, k = s.rest, k-1
        return first_k
```

这些便捷函数让我们能够用一个简单例子来验证 `map_stream` 实现，该例子对从 3 到 7 的整数求平方。

```python
>>> s = integer_stream(3)
>>> s
Stream(3, <...>)
>>> m = map_stream(lambda x: x*x, s)
>>> m
Stream(9, <...>)
>>> first_k_as_list(m, 5)
[9, 16, 25, 36, 49]
```

我们可以用 `filter_stream` 函数，借助埃拉托斯特尼筛法来定义一个质数流：它过滤一个整数流，以移除所有是它第一个元素的倍数的数。通过依次用每个质数进行过滤，所有合数都被从流中移除。

```python
>>> def primes(pos_stream):
        def not_divible(x):
            return x % pos_stream.first != 0
        def compute_rest():
            return primes(filter_stream(not_divible, pos_stream.rest))
        return Stream(pos_stream.first, compute_rest)
```

通过截断 `primes` 流，我们可以枚举质数的任意前缀。

```python
>>> prime_numbers = primes(integer_stream(2))
>>> first_k_as_list(prime_numbers, 7)
[2, 3, 5, 7, 11, 13, 17]
```

流与迭代器的对比在于：流可以被多次传递给纯函数，且每次都会产生相同的结果。质数流不会因为被转换为列表而被"用尽"。也就是说，在把流的前缀转换为列表之后，`prime_numbers` 的 `first` 元素仍然是 2。

```python
>>> prime_numbers.first
2
```

正如递归列表为序列抽象提供了一种简单的实现，流也提供了一种简单、函数式、递归的数据结构，它通过使用高阶函数来实现惰性求值。
