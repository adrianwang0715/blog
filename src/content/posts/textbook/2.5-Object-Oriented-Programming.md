## 2.5   面向对象编程

面向对象编程（object-oriented programming，OOP）是一种组织程序的方法，它把本章中介绍的许多思想汇集在了一起。和抽象数据类型一样，对象在数据的使用与实现之间建立了一道抽象屏障。和消息传递中的派发字典一样，对象会响应行为请求。和可变数据结构一样，对象拥有无法从全局环境直接访问的局部状态。Python 的对象系统提供了新的语法，以促进这些技术用于组织程序。

但对象系统提供的不只是便利；它还开启了一种新的程序设计隐喻：若干相互独立的代理在计算机内部彼此交互。每个对象都把局部状态与行为捆绑在一起，并通过一层数据抽象把二者的复杂性隐藏起来。对象之间相互通信，有益的结果正是在它们的交互中计算出来的。对象不仅能传递消息，还能在同类型的其他对象之间共享行为，并从相关类型那里继承特性。

面向对象编程这一范式有一套自己的词汇，用来强化对象这个隐喻。我们已经看到，对象是一种数据值，它带有可以通过点号标记（dot notation）访问的方法和属性。每个对象还拥有一个类型，称为它的*类（class）*。要实现新的数据类型，我们就创建新的类。

### 2.5.1   对象与类

类是该类型所有对象的模板。每个对象都是某个特定类的*实例（instance）*。我们此前用过的对象都带有内置的类，但新的类也可以像定义新函数那样定义。类定义指定了该类对象所共享的属性和方法。下面我们通过重新审视银行账户这个例子来介绍 `class` 语句。

在介绍局部状态时我们看到，银行账户很自然地被建模为带有 `balance`（余额）的可变值。一个银行账户对象应当具有 `withdraw`（取款）方法，用于更新账户余额，并在余额足够时返回所请求的金额。我们希望还有更多行为来完善账户抽象：银行账户应当能够返回当前余额、返回账户持有人的姓名，并接受存款。

`Account` 类让我们可以创建多个银行账户实例。创建新对象实例这一动作称为*实例化（instantiating）*该类。Python 中实例化一个类的语法与调用函数的语法完全相同。在这里，我们调用 `Account`，并传入参数 `'Jim'`，即账户持有人的姓名。

```python
>>> a = Account('Jim')
```

对象的*属性（attribute）*是与该对象关联的名称-值对（name-value pair），可以通过点号标记访问。属于某个特定对象而非该类所有对象的属性，称为*实例属性（instance attributes）*。每个 `Account` 都有自己的余额和账户持有人姓名，它们是实例属性的例子。在更广泛的编程社区中，实例属性也可能被称为*字段（fields）*、*特性（properties）*或*实例变量（instance variables）*。

```python
>>> a.holder
'Jim'
>>> a.balance
0
```

作用于对象或执行针对该对象的计算的函数称为方法（method）。方法产生的副作用和返回值可以依赖于、也可以改变对象的其他属性。例如，`deposit` 是我们的 `Account` 对象 `a` 的一个方法。它接受一个参数，即要存入的金额，改变对象的 `balance` 属性，并返回改变后的余额。

```python
>>> a.deposit(15)
15
```

在面向对象编程中，我们说方法是在某个特定对象上被*调用（invoked）*的。调用 `withdraw` 方法的结果是：要么取款获得批准，金额被扣除并返回；要么请求被拒绝，账户打印一条错误信息。

```python
>>> a.withdraw(10)  # The withdraw method returns the balance after withdrawal
5
>>> a.balance       # The balance attribute has changed
5
>>> a.withdraw(10)
'Insufficient funds'
```

如上所示，方法的行为可以依赖于对象不断变化的属性。两次以相同参数调用 `withdraw` 会返回不同的结果。

### 2.5.2   定义类

用户自定义的类由 `class` 语句创建，该语句只包含一个子句。`class` 语句先定义类名，然后包含一个语句组（suite），用以定义该类的属性：

```python
class <name>:
    <suite>
```

当执行 `class` 语句时，会创建一个新类，并在当前环境的第一个帧中将它绑定到 `<name>`。随后执行该语句组。在 `class` 语句的 `<suite>` 中通过 `def` 或赋值语句绑定的任何名称，都会创建或修改该类的属性。

类通常是围绕对实例属性的操作来组织的，实例属性是那些不与类本身关联、而与该类每个对象关联的名称-值对。类通过定义一个用于初始化新对象的方法，来规定其对象的实例属性。例如，初始化一个 `Account` 类对象的部分工作，就是把它的起始余额赋为 0。

`class` 语句的 `<suite>` 中包含一些 `def` 语句，它们为该类的对象定义新方法。用于初始化对象的方法在 Python 中有一个特殊的名字 `__init__`（"init" 两侧各有两条下划线），它被称为该类的*构造函数（constructor）*。

```python
>>> class Account:
        def __init__(self, account_holder):
            self.balance = 0
            self.holder = account_holder
```

`Account` 的 `__init__` 方法有两个形式参数。第一个是 `self`，它绑定到新创建的 `Account` 对象；第二个参数 `account_holder` 则绑定到调用该类以进行实例化时传入的参数。

构造函数把实例属性名 `balance` 绑定到 0，还把属性名 `holder` 绑定到 `account_holder` 这个名称的值。形式参数 `account_holder` 是 `__init__` 方法的一个局部名称。另一方面，通过最后一条赋值语句绑定的名称 `holder` 会一直保留，因为它通过点号标记被存储为 `self` 的一个属性。

定义好 `Account` 类之后，我们就可以实例化它了。

```python
>>> a = Account('Jim')
```

这次对 `Account` 类的"调用"创建了一个新对象，它是 `Account` 的一个实例，然后用两个参数调用构造函数 `__init__`：新创建的对象和字符串 `'Jim'`。按照惯例，我们把构造函数的第一个参数命名为 `self`，因为它绑定到正在被实例化的对象。这一惯例几乎被所有 Python 代码所采纳。

现在，我们可以用点号标记访问对象的 `balance` 和 `holder`。

```python
>>> a.balance
0
>>> a.holder
'Jim'
```

**同一性（Identity）。** 每个新的账户实例都有自己的余额属性，其取值独立于同类中的其他对象。

```python
>>> b = Account('Jack')
>>> b.balance = 200
>>> [acc.balance for acc in (a, b)]
[0, 200]
```

为了保证这种独立性，用户自定义类的每一个实例对象都拥有唯一的同一性。对象同一性用 `is` 和 `is not` 运算符来比较。

```python
>>> a is a
True
>>> a is not b
True
```

尽管 `a` 和 `b` 是由完全相同的调用构造出来的，绑定到它们上面的对象却并不相同。和往常一样，用赋值把对象绑定到新名称并不会创建新对象。

```python
>>> c = a
>>> c is a
True
```

只有当某个类（例如 `Account`）以调用表达式语法被实例化时，才会创建属于用户自定义类的新对象。

**方法。** 对象的方法同样由 `class` 语句语句组中的 `def` 语句定义。下面，`deposit` 和 `withdraw` 都被定义为 `Account` 类对象的方法。

```python
>>> class Account:
        def __init__(self, account_holder):
            self.balance = 0
            self.holder = account_holder
        def deposit(self, amount):
            self.balance = self.balance + amount
            return self.balance
        def withdraw(self, amount):
            if amount > self.balance:
                return 'Insufficient funds'
            self.balance = self.balance - amount
            return self.balance
```

虽然方法定义在声明方式上与函数定义没有区别，但方法定义的效果有所不同。由 `class` 语句中的 `def` 语句创建的函数值会绑定到所声明的名称上，但它是在类内部作为属性局部绑定。该值会通过点号标记，从该类的一个实例出发被当作方法来调用。

每个方法定义同样包含一个特殊的第一参数 `self`，它绑定到调用该方法时所作用的对象。例如，假设 `deposit` 在某个特定的 `Account` 对象上被调用，并传入一个参数值，即存款金额。此时对象本身绑定到 `self`，而参数绑定到 `amount`。所有被调用的方法都能通过 `self` 参数访问该对象，因此它们都能访问并操作对象的状态。

要调用这些方法，我们同样使用点号标记，如下所示。

```python
>>> tom_account = Account('Tom')
>>> tom_account.deposit(100)
100
>>> tom_account.withdraw(90)
10
>>> tom_account.withdraw(90)
'Insufficient funds'
>>> tom_account.holder
'Tom'
```

当通过点号标记调用方法时，对象本身（此例中绑定到 `tom_account`）扮演双重角色。首先，它决定了名称 `withdraw` 的含义；`withdraw` 并不是环境中的一个名称，而是 `Account` 类的局部名称。其次，在 `withdraw` 方法被调用时，它绑定到第一个参数 `self`。点号标记求值过程的细节将在下一节给出。

### 2.5.3   消息传递与点表达式

在类中定义的方法，以及在构造函数中赋值（通常是如此）的实例属性，是面向对象编程的基本要素。这两个概念在很大程度上复现了数据值的消息传递实现中派发字典的行为。对象使用点号标记来接收消息，但这些消息不是任意取字符串值的键，而是类的局部名称。对象同样拥有具名的局部状态值（即实例属性），但这些状态可以通过点号标记访问和操作，而无需在实现中使用 `nonlocal` 语句。

消息传递的核心思想是：数据值应当具有行为，即对与其所表示的抽象类型相关的消息作出响应。点号标记是 Python 的一项语法特性，它把消息传递这一隐喻形式化了。使用带有内置对象系统的语言的一个好处是，消息传递可以与其他语言特性（例如赋值语句）无缝协作。我们不需要用不同的消息来"获取"或"设置"与某个局部属性名关联的值；语言语法让我们可以直接使用消息名。

**点表达式。** 代码片段 `tom_account.deposit` 称为一个*点表达式（dot expression）*。点表达式由一个表达式、一个点号和一个名称组成：

```python
<expression> . <name>
```

`<expression>` 可以是任何合法的 Python 表达式，但 `<name>` 必须是一个简单名称（而不是一个求值为名称的表达式）。点表达式求值为：对于作为 `<expression>` 值的那个对象，其名为 `<name>` 的属性的值。

内置函数 `getattr` 也能按名称返回对象的属性。它是与点号标记等价的功能。使用 `getattr`，我们可以像使用派发字典那样，用字符串来查找属性。

```python
>>> getattr(tom_account, 'balance')
10
```

我们还可以用 `hasattr` 测试某个对象是否具有具名属性。

```python
>>> hasattr(tom_account, 'deposit')
True
```

对象的属性包括它的所有实例属性，以及在它的类中定义的所有属性（包括方法）。方法是需要特殊处理的类属性。

**方法与函数。** 当在对象上调用方法时，该对象会被隐式地作为第一个参数传给方法。也就是说，作为点号左侧 `<expression>` 值的那个对象，会被自动作为第一个参数传给点表达式右侧所命名的方法。因此，该对象会绑定到参数 `self`。

为了实现自动绑定 `self`，Python 区分了*函数（functions）*——我们从本书一开始就在创建的东西——和*绑定方法（bound methods）*，后者把一个函数与将要调用该方法所作用的对象结合在一起。绑定方法的值已经与其第一个参数（即调用它时所作用的实例）关联好了，这个参数在方法被调用时会被命名为 `self`。

通过对点表达式返回的值调用 `type`，我们可以在交互式解释器中看到这一区别。作为类的属性，方法只是一个函数；但作为实例的属性，它是绑定方法：

```python
>>> type(Account.deposit)
<class 'function'>
>>> type(tom_account.deposit)
<class 'method'>
```

这两个结果唯一的区别在于，前者是一个标准的两参数函数，参数为 `self` 和 `amount`；后者是一个单参数方法，其中名称 `self` 会在方法被调用时自动绑定到名为 `tom_account` 的对象，而参数 `amount` 会绑定到传给方法的参数。这两个值——无论是函数值还是绑定方法值——都与同一个 `deposit` 函数体相关联。

我们可以用两种方式调用 `deposit`：作为函数和作为绑定方法。在前一种情况下，我们必须显式为 `self` 参数提供一个实参；在后一种情况下，`self` 参数会被自动绑定。

```python
>>> Account.deposit(tom_account, 1001)  # The deposit function takes 2 arguments
1011
>>> tom_account.deposit(1000)           # The deposit method takes 1 argument
2011
```

函数 `getattr` 的行为与点号标记完全一致：如果它的第一个参数是一个对象，而名称是类中定义的方法，那么 `getattr` 返回一个绑定方法值。反之，如果第一个参数是一个类，那么 `getattr` 直接返回属性值，也就是一个普通函数。

**实用指南：命名约定。** 类名按惯例使用 CapWords 约定书写（也叫驼峰命名法 CamelCase，因为名称中间的大写字母看起来像驼峰）。方法名则遵循用下划线分隔小写单词来命名函数的标准约定。

有些情况下，存在一些与对象的维护和一致性有关的实例变量和方法，我们不希望对象的使用者看到或使用它们。它们不属于类所定义的抽象，而属于实现的一部分。Python 的约定规定：如果一个属性名以下划线开头，那么它只应在该类自身的方法内部被访问，而不应由该类的使用者访问。

### 2.5.4   类属性

有些属性值在某个类的所有对象之间共享。这类属性与类本身关联，而不与该类的任何单个实例关联。例如，假设某家银行按固定利率为账户余额支付利息。这个利率可能会变化，但它是所有账户共享的单一值。

类属性由 `class` 语句语句组中、任何方法定义之外的赋值语句创建。在更广泛的开发者社区中，类属性也可能被称为类变量或静态变量。下面这个 `class` 语句为 `Account` 创建了一个名为 `interest` 的类属性。

```python
>>> class Account:
        interest = 0.02            # A class attribute
        def __init__(self, account_holder):
            self.balance = 0
            self.holder = account_holder
        # Additional methods would be defined here
```

这个属性仍然可以从该类的任何实例访问。

```python
>>> tom_account = Account('Tom')
>>> jim_account = Account('Jim')
>>> tom_account.interest
0.02
>>> jim_account.interest
0.02
```

不过，对类属性的一次赋值会改变该属性在类所有实例上的值。

```python
>>> Account.interest = 0.04
>>> tom_account.interest
0.04
>>> jim_account.interest
0.04
```

**属性名的解析。** 我们已经在对象系统中引入了足够多的复杂性，因此必须规定名称是如何解析到具体属性的。毕竟，我们很容易让类属性和实例属性同名。

如我们所见，点表达式由一个表达式、一个点号和一个名称组成：

```python
<expression> . <name>
```

求值一个点表达式时：

1. 求值点号左侧的 `<expression>`，得到点表达式的*对象*。
2. 将 `<name>` 与该对象的实例属性进行匹配；如果存在该名称的属性，就返回它的值。
3. 如果 `<name>` 不在实例属性中，那么就在类中查找 `<name>`，得到一个类属性值。
4. 返回该值，除非它是一个函数——这种情况下改为返回一个绑定方法。

在这个求值过程中，实例属性先于类属性被找到，就像在环境中局部名称优先于全局名称一样。类中定义的方法在这一求值过程的第三步被绑定到点表达式的对象上。在类中查找名称的过程还有一些额外的细节，它们会在我们介绍类继承之后很快出现。

**属性赋值。** 所有左侧含有点表达式的赋值语句，影响的都是该点表达式所对应对象的属性。如果该对象是实例，那么赋值设置的是一个实例属性；如果该对象是类，那么赋值设置的是一个类属性。作为这条规则的结果，对某对象属性的赋值不会影响它所属类的属性。下面的例子说明了这一区别。

如果我们给某个账户实例的具名属性 `interest` 赋值，就会创建一个新的实例属性，它与已有的类属性同名。

```python
>>> jim_account.interest = 0.08
```

该属性值将会从点表达式中返回。

```python
>>> jim_account.interest
0.08
```

然而，类属性 `interest` 仍保留其原值，其他所有账户返回的都是它。

```python
>>> tom_account.interest
0.04
```

对类属性 `interest` 的修改会影响 `tom_account`，但 `jim_account` 的实例属性不受影响。

```python
>>> Account.interest = 0.05  # changing the class attribute
>>> tom_account.interest     # changes instances without like-named instance attributes
0.05
>>> jim_account.interest     # but the existing instance attribute is unaffected
0.08
```

### 2.5.5   继承

在使用面向对象编程范式时，我们常常发现不同的类型之间存在关联。特别是，我们发现相似的类在专门化程度上有所不同。两个类可能拥有相似的属性，但其中一个表示的是另一个的特例。

例如，我们可能想实现一个支票账户，它与标准账户不同。支票账户对每次取款额外收取 1 美元，并且利率更低。下面我们演示所期望的行为。

```python
>>> ch = CheckingAccount('Tom')
>>> ch.interest     # Lower interest rate for checking accounts
0.01
>>> ch.deposit(20)  # Deposits are the same
20
>>> ch.withdraw(5)  # withdrawals decrease balance by an extra charge
14
```

`CheckingAccount` 是 `Account` 的一种专门化。用面向对象编程的术语来说，通用的账户将作为 `CheckingAccount` 的基类（base class），而 `CheckingAccount` 将是 `Account` 的子类（subclass）。（基类也叫*父类（parent class）*和*超类（superclass）*，子类也叫*孩子类（child class）*。）

子类*继承（inherits）*其基类的属性，但可以*覆盖（override）*某些属性，包括某些方法。有了继承，我们只需指定子类与基类之间的不同之处。子类中未指定的任何内容都会自动假定其行为与基类中一致。

除了是一个有用的组织特性之外，继承在对象隐喻中也扮演着角色。继承意在表示类之间的 *is-a*（是一种）关系，这与 *has-a*（拥有一种）关系形成对比。支票账户*是一种*特定类型的账户，所以让 `CheckingAccount` 继承自 `Account` 是继承的恰当用法。另一方面，银行*拥有*一个它所管理的银行账户列表，因此这两者都不应继承自对方。相反，账户对象的列表会自然地表示为银行对象的一个实例属性。

### 2.5.6   使用继承

首先，我们给出 `Account` 类的完整实现，它包含类及其方法的文档字符串。

```python
>>> class Account:
        """A bank account that has a non-negative balance."""
        interest = 0.02
        def __init__(self, account_holder):
            self.balance = 0
            self.holder = account_holder
        def deposit(self, amount):
            """Increase the account balance by amount and return the new balance."""
            self.balance = self.balance + amount
            return self.balance
        def withdraw(self, amount):
            """Decrease the account balance by amount and return the new balance."""
            if amount > self.balance:
                return 'Insufficient funds'
            self.balance = self.balance - amount
            return self.balance
```

`CheckingAccount` 的完整实现如下。我们通过把求值为基类的表达式放在类名之后的括号里来指定继承。

```python
>>> class CheckingAccount(Account):
        """A bank account that charges for withdrawals."""
        withdraw_charge = 1
        interest = 0.01
        def withdraw(self, amount):
            return Account.withdraw(self, amount + self.withdraw_charge)
```

这里，我们引入了一个 `CheckingAccount` 类特有的类属性 `withdraw_charge`。我们为 `interest` 属性赋了一个更低的值。我们还定义了一个新的 `withdraw` 方法来覆盖 `Account` 类中定义的行为。由于类语句组中没有其他语句，其余所有行为都继承自基类 `Account`。

```python
>>> checking = CheckingAccount('Sam')
>>> checking.deposit(10)
10
>>> checking.withdraw(5)
4
>>> checking.interest
0.01
```

表达式 `checking.deposit` 求值为一个用于存款的绑定方法，它是在 `Account` 类中定义的。当 Python 解析一个点表达式中不属于实例属性的名称时，它会在类中查找该名称。事实上，在类中"查找"名称这一动作，会尝试在原始对象所属类的整个继承链中的每一个基类里找到该名称。我们可以递归地定义这个过程。要在一个类中查找一个名称：

1. 如果它是该类中的一个属性名，就返回该属性值。
2. 否则，如果存在基类，就在基类中查找该名称。

对于 `deposit` 这种情况，Python 会先在实例上查找该名称，然后在 `CheckingAccount` 类中查找，最后在定义了 `deposit` 的 `Account` 类中查找。按照我们关于点表达式的求值规则，由于 `deposit` 是在 `checking` 实例所属的类中查找到的函数，该点表达式求值为一个绑定方法值。该方法以参数 10 被调用，也就是调用 deposit 方法，其中 `self` 绑定到 `checking` 对象，`amount` 绑定到 10。

对象的类自始至终保持不变。尽管 `deposit` 方法是在 `Account` 类中找到的，调用 `deposit` 时 `self` 绑定的是 `CheckingAccount` 的一个实例，而不是 `Account` 的实例。

**调用祖先。** 被覆盖的属性仍然可以通过类对象访问。例如，我们实现 `CheckingAccount` 的 `withdraw` 方法时，调用了 `Account` 的 `withdraw` 方法，并传入包含 `withdraw_charge` 的参数。

注意我们调用的是 `self.withdraw_charge`，而不是等价写法 `CheckingAccount.withdraw_charge`。前者的好处在于，继承自 `CheckingAccount` 的类可能会覆盖取款手续费。如果是那样，我们希望 `withdraw` 的实现找到的是新值而不是旧值。

**接口（Interfaces）。** 在面向对象的程序中，不同类型的对象共享相同属性名是极为常见的。*对象接口（object interface）*是属性以及对这些属性所施加条件的集合。例如，所有账户都必须有接受数值参数的 `deposit` 和 `withdraw` 方法，以及一个 `balance` 属性。`Account` 和 `CheckingAccount` 这两个类都实现了这一接口。继承正是以这种方式特别促进了名称共享。在 Java 等一些编程语言中，接口实现必须显式声明。而在 Python、Ruby 和 Go 等语言中，任何具有相应名称的对象都实现了该接口。

你的程序中那些使用对象（而不是实现对象）的部分，如果不对对象类型作任何假设、只对其属性名作假设，那么对未来的变化是最健壮的。也就是说，它们使用的是对象抽象，而不对其实现作任何假设。

例如，假设我们经营一个抽奖活动，希望向一个账户列表中的每个账户存入 5 美元。下面的实现不对这些账户的类型作任何假设，因此它对任何具有 `deposit` 方法的对象类型都同样适用：

```python
>>> def deposit_all(winners, amount=5):
        for account in winners:
            account.deposit(amount)
```

上面的 `deposit_all` 函数只假定每个 `account` 满足账户对象抽象，因此它适用于任何同样实现该接口的账户类。假定某一种特定的账户类会违反账户对象抽象的抽象屏障。例如，下面这个实现不一定适用于新类型的账户：

```python
>>> def deposit_all(winners, amount=5):
        for account in winners:
            Account.deposit(account, amount)
```

我们将在本章后面更详细地讨论这个话题。

### 2.5.7   多重继承

Python 支持子类从多个基类继承属性这一概念，这个语言特性叫*多重继承（multiple inheritance）*。

假设我们有一个 `SavingsAccount` 继承自 `Account`，但每次存款都向客户收取一小笔手续费。

```python
>>> class SavingsAccount(Account):
        deposit_charge = 2
        def deposit(self, amount):
            return Account.deposit(self, amount - self.deposit_charge)
```

然后，一位精明的管理者构想出一个 `AsSeenOnTVAccount` 账户，它兼具 `CheckingAccount` 和 `SavingsAccount` 两方面的最佳特性：取款手续费、存款手续费和低利率。它把支票账户和储蓄账户合二为一！"只要我们做出来，"这位管理者推断道，"就会有人来注册，交上所有这些费用。我们甚至还会送他们一美元。"

```python
>>> class AsSeenOnTVAccount(CheckingAccount, SavingsAccount):
        def __init__(self, account_holder):
            self.holder = account_holder
            self.balance = 1           # A free dollar!
```

事实上，这个实现就是完整的。取款和存款都会产生手续费，分别使用 `CheckingAccount` 和 `SavingsAccount` 中的函数定义。

```python
>>> such_a_deal = AsSeenOnTVAccount("John")
>>> such_a_deal.balance
1
>>> such_a_deal.deposit(20)            # $2 fee from SavingsAccount.deposit
19
>>> such_a_deal.withdraw(5)            # $1 fee from CheckingAccount.withdraw
13
```

无歧义的引用会如预期那样被正确解析：

```python
>>> such_a_deal.deposit_charge
2
>>> such_a_deal.withdraw_charge
1
```

但当引用有歧义时又会怎样呢？比如对 `withdraw` 方法的引用，它在 `Account` 和 `CheckingAccount` 中都有定义。下图描绘了 `AsSeenOnTVAccount` 类的一幅*继承图（inheritance graph）*。每个箭头都从一个子类指向一个基类。

![figure](../img/multiple_inheritance.png)

对于像这样的简单"菱形"结构，Python 按从左到右、再向上的顺序解析名称。在这个例子中，Python 按以下顺序在这些类中查找属性名，直到找到具有该名称的属性为止：

```python
AsSeenOnTVAccount, CheckingAccount, SavingsAccount, Account, object
```

继承顺序问题没有唯一正确的解，因为在某些情况下我们可能更希望让某些被继承的类比其他类具有更高优先级。然而，任何支持多重继承的编程语言都必须以一致的方式选定某种顺序，以便该语言的使用者能够预测其程序的行为。

**延伸阅读。** Python 使用一种称为 C3 方法解析顺序（C3 Method Resolution Ordering）的递归算法来解析该名称。任何类的方法解析顺序都可以通过所有类上的 `mro` 方法查询。

```python
>>> [c.__name__ for c in AsSeenOnTVAccount.mro()]
['AsSeenOnTVAccount', 'CheckingAccount', 'SavingsAccount', 'Account', 'object']
```

寻找方法解析顺序的确切算法不是本书的话题，但[Python 的主要作者对此作了描述](http://python-history.blogspot.com/2010/06/method-resolution-order.html)，并给出了原始论文的参考。

### 2.5.8   函数即对象

在 Python 和许多其他编程语言中，函数本身也是对象，是特殊类的实例。例如，内置于解释器中的函数是 `builtin_function_or_method` 类的实例：

```python
>>> type(pow)
<class 'builtin_function_or_method'>
```

类似地，正如上文针对 `deposit` 函数和方法所展示的，用户定义的函数是 `function` 的实例，而用户定义的方法是 `method` 的实例：

```python
>>> type(Account.deposit)
<class 'function'>
>>> type(tom_account.deposit)
<class 'method'>
```

通过对所得类型调用 `mro`，我们可以看到它们都继承自 `object`，就像我们上面定义的类一样。（名称 `builtin_function_or_method`、`function` 和 `method` 并未绑定在全局命名空间中，因此我们无法直接在它们上面调用 `mro`。）

```python
>>> [c.__name__ for c in type(pow).mro()]
['builtin_function_or_method', 'object']
>>> [c.__name__ for c in type(Account.deposit).mro()]
['function', 'object']
>>> [c.__name__ for c in type(tom_account.deposit).mro()]
['method', 'object']
```

既然函数是对象，它们就像任何其他对象一样拥有属性。例如，所有函数都有一个 `__name__` 属性：

```python
>>> pow.__name__
'pow'
```

属性也可以添加到用户定义的函数上，而且大多数已有属性都可以修改。然而，方法和内置函数不允许添加或修改属性。

```python
>>> def my_pow(x, y):
        return pow(x, y)
```

```python
>>> my_pow
<function my_pow at 0x7f77b2558270>
>>> my_pow.__name__ = "power"    # change attribute
>>> my_pow
<function power at 0x7f77b2558270>
>>> my_pow.value = 42   # new attribute
>>> my_pow.value
42
```

（注意：从 Python 3.3 起，函数拥有一个 `__qualname__` 属性，在很多地方用它代替 `__name__`。在上面的例子中，要在 Python 3.3 中达到同样的行为，必须修改的是 `__qualname__` 属性而不是 `__name__`。）

函数属性让我们能够把函数特定的数据存储在函数自身之上，而不必污染全局命名空间。

### 2.5.9   对象的作用

Python 对象系统的设计目标是让数据抽象和消息传递既方便又灵活。类、方法、继承和点表达式这些专门的语法，都让我们能够在程序中把对象隐喻形式化，从而提升我们组织大型程序的能力。

特别是，我们希望对象系统促进程序不同方面之间的*关注点分离（separation of concerns）*。程序中的每个对象都封装并管理着程序状态的一部分，而每个 `class` 语句都定义了一些函数，它们实现着程序整体逻辑的一部分。抽象屏障强制维护了大型程序不同方面之间的边界。

面向对象编程特别适合那些对由彼此独立又相互作用的部件组成的系统进行建模的程序。例如，不同用户在社交网络中交互，不同角色在游戏中交互，不同形状在物理仿真中交互。在表示这类系统时，程序中的对象往往自然地对应于被建模系统中的对象，而类则代表它们的类型和关系。

另一方面，对于实现某些抽象来说，类可能并非最佳机制。函数式抽象为表示输入和输出之间的关系提供了一种更自然的隐喻。人不应当感到非得把程序中的每一段逻辑都塞进一个类里，尤其是在为操作数据而定义独立的函数更为自然的时候。函数同样能够实现关注点分离。

像 Python 这样的多范式语言允许程序员把不同的组织范式与恰当的问题相匹配。学会判断何时应当引入一个新类而不是一个新函数，以便简化程序或使之模块化，是软件工程中一项重要的设计技能，值得仔细关注。
