# 第 2 章：用对象构建抽象

## 2.4   可变数据（mutable data）

我们已经看到，抽象对于帮助我们应对大型系统的复杂性是何等重要。有效的程序综合同样需要组织原则，来指导我们构建程序的整体设计。特别地，我们需要一些策略来帮助我们组织大型系统，使其具有*模块化*（modular）的特性，也就是能够被"自然地"划分为若干连贯的部分，各部分可以被独立地开发和维护。

创建模块化程序的一种强大技术，是引入可以随时间改变状态的新型数据。这样一来，单个数据对象就能够表示某种独立于程序其余部分而演化的东西。一个变化中的对象，其行为可能受其历史影响，就像一个现实世界中的实体一样。为数据添加状态，是本章最终目标——面向对象编程——的一个基本组成部分。

到目前为止我们介绍过的原生数据类型 —— 数字、布尔值、元组、区间和字符串 —— 全都是*不可变*（immutable）对象类型。虽然名字在程序执行过程中可能会重新绑定到环境中不同的值，但值本身并不会改变。*可变对象（mutable object）*（也称为可变值）则可以在程序执行过程中发生变化。

### 2.4.1   列表

`list` 是 Python 中最有用、最灵活的序列类型。列表（list）与元组类似，但它是可变的：方法调用和赋值语句都可以改变列表的内容。

我们可以通过一个（大幅简化的）扑克牌历史示例，来引入许多列表修改操作。示例中的注释描述了每次方法调用的效果。

扑克牌发明于中国，大约在 9 世纪左右。早期的一副牌有三种花色，对应着货币的面额。

```python
>>> chinese_suits = ['coin', 'string', 'myriad']  # A list literal
>>> suits = chinese_suits                         # Two names refer to the same list
```

随着纸牌传入欧洲（可能是经由埃及），西班牙牌中只剩下金币这一花色（*oro*）。

```python
>>> suits.pop()             # Remove and return the final element
'myriad'
>>> suits.remove('string')  # Remove the first element that equals the argument
```

之后又增加了三种花色（它们的名称和设计随时间不断演变），

```python
>>> suits.append('cup')              # Add an element to the end
>>> suits.extend(['sword', 'club'])  # Add all elements of a list to the end
```

意大利人把剑称为 *spades*。

```python
>>> suits[2] = 'spade'  # Replace an element
```

于是就有了传统意大利牌的花色。

```python
>>> suits
['coin', 'cup', 'spade', 'club']
```

而今天在美国使用的法国变体则改变了前两种花色：

```python
>>> suits[0:2] = ['heart', 'diamond']  # Replace a slice
>>> suits
['heart', 'diamond', 'spade', 'club']
```

此外也存在用于插入、排序和反转列表的方法。所有这些*修改操作*（mutation operation）都改变列表的值；它们并不创建新的列表对象。

**共享与标识。** 由于我们一直在修改同一个列表，而不是创建新列表，所以绑定到名字 `chinese_suits` 的对象也发生了变化，因为它与绑定到 `suits` 的是同一个列表对象！

```python
>>> chinese_suits  # This name co-refers with "suits" to the same list
['heart', 'diamond', 'spade', 'club']
```

这种行为是全新的。在此之前，如果一个名字没有出现在某条语句中，那么它的值就不会受该语句影响。而在可变数据的情况下，对一个名字调用的方法可以同时影响另一个名字。

这个示例的环境图展示了，只涉及 `suits` 的语句是如何改变绑定到 `chinese` 的值的。请逐步执行下面示例的每一行，观察这些变化。

```python
chinese = ['coin', 'string', 'myriad']
suits = chinese
suits.pop()
suits.remove('string')
suits.append('cup')
suits.extend(['sword', 'club'])
suits[2] = 'spade'
suits[0:2] = ['heart', 'diamond']
```

可以使用 `list` 构造函数复制列表。对一个列表的修改不会影响另一个，除非它们共享结构。

```python
>>> nest = list(suits)  # Bind "nest" to a second list with the same elements
>>> nest[0] = suits     # Create a nested list
```

根据这个环境，改变 `suits` 所引用的列表，会影响作为 `nest` 第一个元素的嵌套列表，但不会影响其他元素。

```python
>>> suits.insert(2, 'Joker')  # Insert an element at index 2, shifting the rest
>>> nest
[['heart', 'diamond', 'Joker', 'spade', 'club'], 'diamond', 'spade', 'club']
```

同样地，撤销 `nest` 第一个元素中的这一改动，也会改变 `suit`。

```python
>>> nest[0].pop(2)
'Joker'
>>> suits
['heart', 'diamond', 'spade', 'club']
```

逐行执行这个示例，将展示嵌套列表的表示方式。

```python
suits = ['heart', 'diamond', 'spade', 'club']
nest = list(suits)
nest[0] = suits
suits.insert(2, 'Joker')
j = nest[0].pop(2)
```

由于两个列表可能内容相同但实际上是不同的列表，我们需要一种方式来检验两个对象是否相同。Python 提供了两个比较运算符，称为 `is` 和 `is not`，用来检验两个表达式是否求值为完全相同的对象。如果两个对象在其当前值上相等，且对其中一个的任何改动都会反映到另一个上，那么它们就是相同的。标识（identity）比相等（equality）是更强的条件。

```python
>>> suits is nest[0]
True
>>> suits is ['heart', 'diamond', 'spade', 'club']
False
>>> suits == ['heart', 'diamond', 'spade', 'club']
True
```

最后两个比较说明了 `is` 与 `==` 之间的区别。前者检查标识，而后者检查内容是否相等。

**列表推导式。** 列表推导式使用一种扩展语法来创建列表，类似于生成器表达式的语法。

例如，`unicodedata` 模块记录了 Unicode 字符集中每个字符的官方名称。我们可以查找与名称对应的字符，包括扑克牌花色对应的字符。

```python
>>> from unicodedata import lookup
>>> [lookup('WHITE ' + s.upper() + ' SUIT') for s in suits]
['♡', '♢', '♤', '♧']
```

列表推导式强化了序列处理的一般方法，因为 `list` 本身也是一种序列数据类型。

### 2.4.2   字典

字典（dictionary）是 Python 内置的数据类型，用于存储和操作对应关系。字典包含键值对，其中键和值都是对象。字典的用途是提供一种抽象，用来存储和检索那些不以连续整数、而以描述性键作为索引的值。

字符串常被用作键，因为字符串是我们表示事物名称的惯用方式。下面这个字典字面量给出了各种罗马数字的值。

```python
>>> numerals = {'I': 1.0, 'V': 5, 'X': 10}
```

通过键查找值，使用的是我们先前用于序列的元素选择运算符。

```python
>>> numerals['X']
10
```

一个字典中每个键至多只能有一个值。添加新的键值对以及修改某个键的现有值，都可以通过赋值语句完成。

```python
>>> numerals['I'] = 1
>>> numerals['L'] = 50
>>> numerals
{'I': 1, 'X': 10, 'L': 50, 'V': 5}
```

注意 `'L'` 并没有被添加在上方输出的末尾。字典是键值对的无序集合。当我们打印字典时，键和值会以某种顺序呈现，但作为语言的使用者，我们无法预测那会是什么顺序。

字典也可以出现在环境图中。

```python
numerals = {'I': 1, 'V': 5, 'X': 10}
numerals['L'] = 50
```

字典抽象还支持各种整体迭代其内容的方法。方法 `keys`、`values` 和 `items` 都返回可迭代的值。

```python
>>> sum(numerals.values())
66
```

通过调用 `dict` 构造函数，可以将键值对组成的列表转换为字典。

```python
>>> dict([(3, 9), (4, 16), (5, 25)])
{3: 9, 4: 16, 5: 25}
```

字典确实有一些限制：

- 字典的键不能是可变内置类型的对象。
- 对于给定的键，至多只能有一个值。

第一条限制与 Python 中字典的底层实现有关。该实现的细节不是本文的主题。直观地说，可以把键理解为告诉 Python 在内存中到何处查找那个键值对；如果键发生变化，该键值对的位置可能就丢失了。

第二条限制是字典抽象的结果，字典的设计目的就是按键存储和检索值。只有当字典中至多存在一个这样的值时，我们才能检索到某个键*那个*值。

字典实现的一个有用方法是 `get`，它返回某个键对应的值（如果该键存在），否则返回一个默认值。`get` 的参数是键和默认值。

```python
>>> numerals.get('A', 0)
0
>>> numerals.get('V', 0)
5
```

字典也有与列表和生成器表达式类似的推导式语法。求值一个字典推导式会产生一个新的字典对象。

```python
>>> {x: x*x for x in range(3,6)}
{3: 9, 4: 16, 5: 25}
```

### 2.4.3   局部状态

列表和字典具有*局部状态*（local state）：它们是不断变化的值，在程序执行的任何时刻都具有某些特定内容。状态这个词意味着一个不断演化的过程，其中状态可能发生变化。

函数也可以具有局部状态。例如，让我们定义一个函数来模拟从银行账户中取钱的过程。我们将创建一个名为 `withdraw` 的函数，它接受要取出的金额作为参数。如果账户中的钱足以支付这次取款，那么 `withdraw` 将返回取款后剩余的余额。否则，`withdraw` 将返回消息 `'Insufficient funds'`。例如，如果账户中最初有 100 美元，我们希望反复调用 withdraw 得到如下一系列返回值：

```python
>>> withdraw(25)
75
>>> withdraw(25)
50
>>> withdraw(60)
'Insufficient funds'
>>> withdraw(15)
35
```

上面，表达式 `withdraw(25)` 求值两次却得到了不同的值。因此，这个用户定义的函数是非纯的。调用该函数不仅返回一个值，还会产生以某种方式改变该函数的副作用，使得下一次用相同参数调用时会返回不同结果。这一副作用源于 `withdraw` 改变了其局部环境帧之外的某个名字-值绑定。

为了让 `withdraw` 有意义，它必须在创建时带有一个初始账户余额。函数 `make_withdraw` 是一个高阶函数，接受起始余额作为参数。`withdraw` 函数就是它的返回值。

```python
>>> withdraw = make_withdraw(100)
```

实现 `make_withdraw` 需要一种新的语句：`nonlocal` 语句。当我们调用 `make_withdraw` 时，我们把名字 `balance` 绑定到初始金额。然后我们定义并返回一个局部函数 `withdraw`，它在被调用时更新并返回 `balance` 的值。

```python
>>> def make_withdraw(balance):
        """Return a withdraw function that draws down balance with each call."""
        def withdraw(amount):
            nonlocal balance                 # Declare the name "balance" nonlocal
            if amount > balance:
                return 'Insufficient funds'
            balance = balance - amount       # Re-bind the existing balance name
            return balance
        return withdraw
```

这个实现中新颖的部分是 `nonlocal` 语句，它规定：每当我们改变名字 `balance` 的绑定时，该绑定都在 `balance` 已经被绑定的第一个帧中被改变。回忆一下，如果没有 `nonlocal` 语句，赋值语句总是会在环境的第一个帧中绑定名字。`nonlocal` 语句表明，该名字出现在环境中除第一个（局部）帧或最后一个（全局）帧之外的某个地方。

下面的环境图说明了多次调用由 `make_withdraw` 创建的函数所产生的效果。

```python
def make_withdraw(balance):
    def withdraw(amount):
        nonlocal balance
        if amount > balance:
            return 'Insufficient funds'
        balance = balance - amount
        return balance
    return withdraw

wd = make_withdraw(20)
wd(5)
wd(3)
```

第一个 def 语句具有通常的效果：它创建一个新的用户定义函数，并在全局帧中把名字 `make_withdraw` 绑定到该函数。随后对 `make_withdraw` 的调用创建并返回一个局部定义的函数 `withdraw`。名字 `balance` 绑定在该函数的父帧中。关键在于，在本例余下的过程中，名字 `balance` 只会存在这一个绑定。

接下来，我们求值一个表达式，用金额 5 调用这个绑定到名字 `wd` 的函数。`withdraw` 的函数体在一个新环境中执行，该环境扩展了定义 `withdraw` 时的环境。追踪 `withdraw` 的求值效果，说明了 Python 中 `nonlocal` 语句的效果：第一个局部帧之外的名字可以被赋值语句改变。

```python
def make_withdraw(balance):
    def withdraw(amount):
        nonlocal balance
        if amount > balance:
            return 'Insufficient funds'
        balance = balance - amount
        return balance
    return withdraw

wd = make_withdraw(20)
wd(5)
wd(3)
```

`nonlocal` 语句改变了 `withdraw` 定义中所有剩余的赋值语句。在执行 `nonlocal balance` 之后，任何左侧为 `balance` 的赋值语句都不会在当前环境的第一个帧中绑定 `balance`。相反，它会找到 `balance` 已被定义的第一个帧，并在该帧中重新绑定这个名字。如果 `balance` 此前没有被绑定到任何值，那么 `nonlocal` 语句将报错。

通过改变 `balance` 的绑定，我们也改变了 `withdraw` 函数本身。下一次调用它时，名字 `balance` 将求值为 15 而不是 20。因此，当我们第二次调用 `withdraw` 时，会看到它的返回值是 12 而不是 17。第一次调用对 `balance` 的改变影响了第二次调用的结果。

```python
def make_withdraw(balance):
    def withdraw(amount):
        nonlocal balance
        if amount > balance:
            return 'Insufficient funds'
        balance = balance - amount
        return balance
    return withdraw

wd = make_withdraw(20)
wd(5)
wd(3)
```

对 `withdraw` 的第二次调用确实照常创建了第二个局部帧。然而，两个 `withdraw` 帧拥有相同的父帧。也就是说，它们都扩展了 `make_withdraw` 的环境，而该环境中包含 `balance` 的绑定。因此，它们共享那个特定的名字绑定。调用 `withdraw` 会产生副作用，改变未来对 `withdraw` 的调用将要扩展的环境。`nonlocal` 语句允许 `withdraw` 改变 `make_withdraw` 帧中的一个名字绑定。

自从我们第一次遇到嵌套的 `def` 语句以来，我们一直观察到：局部定义的函数可以查找其局部帧之外的名字。*访问*非局部名字并不需要 `nonlocal` 语句。相比之下，只有在使用了 `nonlocal` 语句之后，函数才能*改变*这些帧中名字的绑定。

**实用指南。** 通过引入 `nonlocal` 语句，我们给赋值语句赋予了双重角色。它们要么改变局部绑定，要么改变非局部绑定。事实上，赋值语句本来就具有双重角色：它们要么创建新的绑定，要么重新绑定已有的名字。赋值还可以改变列表和字典的内容。Python 赋值的多重角色可能使执行赋值语句的效果变得难以看清。作为程序员，你需要清晰地记录你的代码，以便他人能够理解赋值的实际效果。

**Python 特性。** 这种非局部赋值模式是具有高阶函数和词法作用域的编程语言的一个普遍特征。大多数其他语言根本不需要 `nonlocal` 语句。相反，非局部赋值往往是赋值语句的默认行为。

Python 还有一个关于名字查找的不寻常限制：在函数体内部，某个名字的所有出现都必须引用同一个帧。因此，Python 无法先在非局部帧中查找某个名字的值，然后又在局部帧中绑定同一个名字，因为同一个名字会在同一个函数中的两个不同帧里被访问。这一限制使得 Python 可以在执行函数体之前预先计算出每个名字位于哪个帧。当这一限制被违反时，会产生一条令人困惑的错误信息。为了演示，下面重复了 `make_withdraw` 示例，但去掉了 `nonlocal` 语句。

```python
def make_withdraw(balance):
    def withdraw(amount):
        if amount > balance:
            return 'Insufficient funds'
        balance = balance - amount
        return balance
    return withdraw

wd = make_withdraw(20)
wd(5)
```

出现这个 `UnboundLocalError` 是因为 `balance` 在第 5 行被局部赋值，因此 Python 假设对 `balance` 的所有引用也都必须出现在局部帧中。这个错误发生在第 5 行被执行*之前*，这意味着 Python 在第 3 行执行之前就已经以某种方式考虑了第 5 行。在学习解释器设计时，我们将会看到，在执行函数体之前预先计算关于函数体的事实是相当常见的。在这个例子中，Python 的预处理限制了 `balance` 可以出现的帧，从而使得该名字无法被找到。添加 `nonlocal` 语句可以纠正这个错误。`nonlocal` 语句在 Python 2 中并不存在。

### 2.4.4   非局部赋值的好处

非局部赋值是我们把程序视为一组独立而自主的*对象*（object）这一道路上的重要一步，这些对象彼此交互，但各自管理自己的内部状态。

特别地，非局部赋值使我们有能力维护某种局部于某个函数、但在对该函数的连续调用中不断演化的状态。与某个特定 withdraw 函数相关联的 `balance` 在该函数的所有调用之间共享。然而，与某个 withdraw 实例相关联的 balance 绑定，对程序其余部分是不可访问的。只有 `wd` 与定义它的 `make_withdraw` 帧相关联。如果再次调用 `make_withdraw`，它将创建一个单独的帧，其中带有 `balance` 的一个单独绑定。

我们可以扩展这个示例来说明这一点。第二次调用 `make_withdraw` 会返回第二个 `withdraw` 函数，它具有不同的父帧。我们在全局帧中把这个第二个函数绑定到名字 `wd2`。

```python
def make_withdraw(balance):
    def withdraw(amount):
        nonlocal balance
        if amount > balance:
            return 'Insufficient funds'
        balance = balance - amount
        return balance
    return withdraw

wd = make_withdraw(20)
wd2 = make_withdraw(7)
wd2(6)
wd(8)
```

现在，我们看到名字 `balance` 实际上在两个不同的帧中有两个绑定，并且每个 `withdraw` 函数都有不同的父帧。名字 `wd` 绑定到一个余额为 20 的函数，而 `wd2` 绑定到另一个余额为 7 的函数。

调用 `wd2` 改变了它非局部的 `balance` 名字的绑定，但不影响绑定到名字 `withdraw` 的那个函数。未来对 `wd` 的调用不受 `wd2` 余额变化的影响；它的余额仍然是 20。

```python
def make_withdraw(balance):
    def withdraw(amount):
        nonlocal balance
        if amount > balance:
            return 'Insufficient funds'
        balance = balance - amount
        return balance
    return withdraw

wd = make_withdraw(20)
wd2 = make_withdraw(7)
wd2(6)
wd(8)
```

这样，每个 `withdraw` 实例都维护自己的余额状态，但该状态对程序中的任何其他函数都是不可访问的。从更高的层次来看，我们创建了一个银行账户的抽象，它管理自己的内部状态，但其行为方式模拟了现实世界中的账户：它根据自己的取款请求历史随时间变化。

### 2.4.5   非局部赋值的代价

我们的计算环境模型可以干净地扩展，用来解释非局部赋值的效果。然而，非局部赋值在我们思考名字和值的方式中引入了一些重要的微妙之处。

在此之前，我们的值不会改变；只有名字和绑定会改变。当两个名字 `a` 和 `b` 都绑定到值 4 时，它们绑定的是同一个 4 还是不同的 4 并不重要。就我们所能分辨的而言，只有一个从不改变的 4 对象。

然而，带状态的函数并非如此。当两个名字 `wd` 和 `wd2` 都绑定到一个 `withdraw` 函数时，它们绑定的是同一个函数还是该函数的不同实例，这*确实*很重要。考虑下面这个示例，它与我们刚刚分析的那个形成对比。在这种情况下，调用名为 `wd2` 的函数确实改变了名为 `wd` 的函数的值，因为两个名字引用的是同一个函数。

```python
def make_withdraw(balance):
    def withdraw(amount):
        nonlocal balance
        if amount > balance:
            return 'Insufficient funds'
        balance = balance - amount
        return balance
    return withdraw

wd = make_withdraw(12)
wd2 = wd
wd2(1)
wd(1)
```

在现实世界中，两个名字共同指代同一个值是常见的事，在程序中也是如此。但是，随着值随时间变化，我们必须非常小心地理解改变会对其他可能指代这些值的名字产生何种影响。

正确分析带有非局部赋值的代码的关键，是记住只有函数调用才能引入新的帧。赋值语句总是改变已有帧中的绑定。在这个例子中，除非 `make_withdraw` 被调用两次，否则 `balance` 只能有一个绑定。

**同一性与变化。** 这些微妙之处之所以出现，是因为通过引入改变非局部环境的非纯函数，我们改变了表达式的性质。一个只包含纯函数调用的表达式是*引用透明*（referentially transparent）的；如果我们把其中一个子表达式替换为该子表达式的值，它的值不会改变。

重新绑定操作违反了引用透明的条件，因为它们做的不仅仅是返回一个值；它们还改变环境。当我们引入任意重新绑定时，我们就会遇到一个棘手的认识论问题：两个值相同意味着什么。在我们的计算环境模型中，两个分别定义的函数是不相同的，因为对其中一个的改变可能不会反映到另一个中。

一般来说，只要我们从不去修改数据对象，我们就可以把复合数据对象视为其各个组成部分的总和。例如，有理数由它的分子和分母共同确定。但在存在变化的情况下，这种观点不再成立，此时复合数据对象具有一种"标识"，它不同于构成它的那些部分。即使我们通过取款改变了余额，一个银行账户仍然是"同一个"银行账户；反过来说，我们可能有两个恰好余额相同的银行账户，但它们是不同的对象。

尽管非局部赋值引入了种种复杂之处，它仍然是创建模块化程序的强大工具。程序中对应于不同环境帧的不同部分，可以在程序执行过程中独立地演化。此外，利用带局部状态的函数，我们能够实现可变数据类型。事实上，我们可以实现与上面介绍的内置 `list` 和 `dict` 类型等价的抽象数据类型。

### 2.4.6   实现列表和字典

列表是序列，就像元组一样。Python 语言不允许我们访问列表的实现，只允许我们使用序列抽象以及本节中介绍的那些修改方法。为了克服这种由语言强加的抽象屏障，我们可以开发一种列表的函数式实现，同样使用递归表示。本节还有第二个目的：加深我们对分派函数的理解。

我们将把列表实现为一个函数，它以递归列表作为其局部状态。列表需要具有标识，就像任何可变值一样。特别地，我们不能用 `None` 来表示空的可变列表，因为两个空列表并不是相同的值（例如，向其中一个追加元素不会追加到另一个），而 `None is None` 却成立。另一方面，两个各自以 `empty_rlist` 作为局部状态的不同函数，就足以区分两个空列表。

我们的可变列表是一个分派函数（dispatch function），正如我们函数式实现的序对也是一个分派函数一样。它把输入"消息"与已知消息进行比较，并针对每个不同的输入采取相应的动作。我们的可变列表响应五种不同的消息。前两种实现序列抽象的行为。接下来两种添加或移除列表的第一个元素。最后一种消息返回整个列表内容的字符串表示。

```python
>>> def mutable_rlist():
        """Return a functional implementation of a mutable recursive list."""
        contents = empty_rlist
        def dispatch(message, value=None):
            nonlocal contents
            if message == 'len':
                return len_rlist(contents)
            elif message == 'getitem':
                return getitem_rlist(contents, value)
            elif message == 'push_first':
                contents = rlist(value, contents)
            elif message == 'pop_first':
                f = first(contents)
                contents = rest(contents)
                return f
            elif message == 'str':
                return str(contents)
        return dispatch
```

我们还可以添加一个便捷函数，用于从任何内置序列构造一个函数式实现的递归列表，只需按逆序逐个添加每个元素即可。

```python
>>> def to_mutable_rlist(source):
        """Return a functional list with the same contents as source."""
        s = mutable_rlist()
        for element in reversed(source):
            s('push_first', element)
        return s
```

在上面的定义中，函数 `reversed` 接受并返回一个可迭代值；它是又一个处理序列的函数的例子。

至此，我们可以构造一个函数式实现的列表了。注意，列表本身就是一个函数。

```python
>>> s = to_mutable_rlist(suits)
>>> type(s)
<class 'function'>
>>> s('str')
"('heart', ('diamond', ('spade', ('club', None))))"
```

此外，我们可以向列表 `s` 传递消息来改变它的内容，例如移除第一个元素。

```python
>>> s('pop_first')
'heart'
>>> s('str')
"('diamond', ('spade', ('club', None)))"
```

原则上，`push_first` 和 `pop_first` 这两个操作足以对列表做任意修改。我们总是可以先把列表完全清空，然后用期望的结果替换它原有的内容。

**消息传递。** 假以时日，我们可以实现 Python 列表的许多有用修改操作，例如 `extend` 和 `insert`。我们会有两种选择：可以把它们全部实现为函数，利用已有的消息 `pop_first` 和 `push_first` 来完成所有修改；或者，我们可以在 `dispatch` 的函数体中添加额外的 `elif` 子句，每个子句检查一条消息（例如 `'extend'`），并直接对 `contents` 施加相应的修改。

第二种方法把所有对某个数据值的操作的逻辑，都封装在一个响应不同消息的函数中，这称为消息传递（message passing）。使用消息传递的程序定义分派函数，每个分派函数都可以有自己的局部状态，并通过把"消息"作为第一个参数传给这些函数来组织计算。这些消息是与特定行为相对应的字符串。

可以想象，在 `dispatch` 的函数体中按名字枚举所有这些消息会变得冗长且容易出错。下一节介绍的 Python 字典提供了一种数据类型，可以帮助我们管理消息与操作之间的映射。

**实现字典。** 我们可以实现一个符合字典抽象的抽象数据类型，把它表示为一个记录列表，其中每条记录都是一个二元素列表，由一个键和与其关联的值组成。

```python
>>> def dictionary():
        """Return a functional implementation of a dictionary."""
        records = []
        def getitem(key):
            for k, v in records:
                if k == key:
                    return v
        def setitem(key, value):
            for item in records:
                if item[0] == key:
                    item[1] = value
                    return
            records.append([key, value])
        def dispatch(message, key=None, value=None):
            if message == 'getitem':
                return getitem(key)
            elif message == 'setitem':
                setitem(key, value)
            elif message == 'keys':
                return tuple(k for k, _ in records)
            elif message == 'values':
                return tuple(v for _, v in records)
        return dispatch
```

我们再次使用消息传递方法来组织我们的实现。我们支持了四条消息：`getitem`、`setitem`、`keys` 和 `values`。要按键查找值，我们遍历记录以找到匹配的键。要为某个键插入值，我们遍历记录，看看是否已经有一条具有该键的记录。如果没有，我们就形成一条新记录。如果已经有一条具有该键的记录，我们就把该记录的值设为指定的新值。

现在我们就可以使用我们的实现来存储和检索值了。

```python
>>> d = dictionary()
>>> d('setitem', 3, 9)
>>> d('setitem', 4, 16)
>>> d('getitem', 3)
9
>>> d('getitem', 4)
16
>>> d('keys')
(3, 4)
>>> d('values')
(9, 16)
```

这个字典实现*并不*针对快速的记录查找进行优化，因为对消息 `'getitem'` 的每次响应都必须遍历整个 `records` 列表。内置的字典类型效率要高得多。

### 2.4.7   分派字典

分派函数是为抽象数据类型实现消息传递接口的一种通用方法。为了实现消息分派，我们迄今一直使用一个大型条件语句，通过消息字符串来查找函数值。

内置的字典数据类型提供了一种按键查找值的通用方法。我们可以用带字符串键的字典来代替分派函数来实现抽象数据类型。

下面这个可变的 `account` 数据类型就是用一个字典实现的。它有一个构造函数 `account` 和选择函数 `check_balance`，以及用于 `deposit`（存款）或 `withdraw`（取款）的函数。此外，账户的局部状态与实现其行为的那些函数一起存储在字典中。

```python
def account(initial_balance):
    def deposit(amount):
        dispatch['balance'] += amount
        return dispatch['balance']
    def withdraw(amount):
        if amount > dispatch['balance']:
            return 'Insufficient funds'
        dispatch['balance'] -= amount
        return dispatch['balance']
    dispatch = {'deposit':   deposit,
                'withdraw':  withdraw,
                'balance':   initial_balance}
    return dispatch

def withdraw(account, amount):
    return account['withdraw'](amount)
def deposit(account, amount):
    return account['deposit'](amount)
def check_balance(account):
    return account['balance']

a = account(20)
deposit(a, 5)
withdraw(a, 17)
check_balance(a)
```

`account` 构造函数体中的名字 `dispatch` 绑定到一个字典，该字典以账户所接受的消息作为键。*余额*是一个数字，而消息 *deposit* 和 *withdraw* 则绑定到函数。这些函数可以访问 `dispatch` 字典，因此它们能够读取和改变余额。通过把余额存储在分派字典中，而不是直接存储在 `account` 帧中，我们避免了在 `deposit` 和 `withdraw` 中使用 `nonlocal` 语句。

运算符 `+=` 和 `-=` 在 Python（以及许多其他语言）中是查找与重新赋值的简写形式。下面最后两行是等价的。

```python
>>> a = 2
>>> a = a + 1
>>> a += 1
```

### 2.4.8   约束传播

可变数据使我们能够模拟带有变化的系统，同时也使我们能够构建新型的抽象。在这个扩展示例中，我们结合非局部赋值、列表和字典，构建一个*基于约束的系统*（constraint-based system），它支持多方向的计算。把程序表达为约束是一种*声明式编程*（declarative programming），在这种编程范式中，程序员声明待求解问题的结构，而把问题究竟如何被计算出来的细节抽象掉。

计算机程序传统上被组织为单向的计算，即对预先指定的参数执行操作以产生期望的输出。另一方面，我们常常希望用各个量之间的关系来对系统建模。例如，我们之前考虑过理想气体定律，它通过玻尔兹曼常数（`k`）把理想气体的压强（`p`）、体积（`v`）、物质的量（`n`）和温度（`t`）联系起来：

```python
p * v = n * k * t
```

这样一个方程不是单向的。给定其中任意四个量，我们都可以用这个方程计算出第五个。然而，把该方程翻译成传统计算机语言会迫使我们选择其中一个量，用其他四个量来计算它。于是，一个用于计算压强的函数就无法用来计算温度，即使这两个量的计算都源自同一个方程。

本节中，我们勾勒一个线性关系通用模型的设计。我们定义量之间成立的基本约束，例如一个 `adder(a, b, c)` 约束，它强制实现数学关系 `a + b = c`。

我们还定义一种组合手段，使得基本约束可以被组合起来，表达更复杂的关系。这样，我们的程序就类似于一种编程语言。我们通过构造一个网络来组合约束，网络中的约束由连接器（connector）连接。连接器是一个"持有"某个值、并可能参与一个或多个约束的对象。

例如，我们知道华氏温度与摄氏温度之间的关系是：

```python
9 * c = 5 * (f - 32)
```

这个方程是 `c` 与 `f` 之间的一个复杂约束。这样一个约束可以被视为一个由基本 `adder`、`multiplier` 和 `constant` 约束组成的网络。

![figure](../img/constraints.png)

在这个图中，我们在左侧看到一个带三个端子的乘法器盒子，端子分别标记为 `a`、`b` 和 `c`。它们把乘法器与网络其余部分连接如下：`a` 端子连接到连接器 `celsius`，该连接器将持有摄氏温度。`b` 端子连接到一个连接器 `w`，该连接器又连接到一个持有 9 的常量盒子。`c` 端子被乘法器盒子约束为 `a` 与 `b` 的乘积，它连接到另一个乘法器盒子的 `c` 端子，后者的 `b` 连接到一个常量 5，`a` 则连接到和约束中的某一项。

通过这样一个网络进行的计算过程如下：当一个连接器被赋予一个值（由用户或由与它相连的某个约束盒子赋予）时，它会唤醒所有与它关联的约束（除了刚刚唤醒它的那个约束），通知它们自己有了一个值。然后，每个被唤醒的约束盒子会查看它的各个连接器，看是否有足够的信息来确定某个连接器的值。如果有，该盒子就设置那个连接器，这个连接器接着又唤醒它所有关联的约束，如此继续下去。例如，在摄氏与华氏之间的转换中，`w`、`x` 和 `y` 立刻被常量盒子分别设置为 9、5 和 32。这些连接器唤醒乘法器和加法器，而它们判定信息不足，无法继续。如果用户（或网络的某个其他部分）把 `celsius` 连接器设置为一个值（比如 25），最左边的乘法器就会被唤醒，它会把 `u` 设置为 `25 * 9 = 225`。然后 `u` 唤醒第二个乘法器，后者把 `v` 设置为 45，接着 `v` 唤醒加法器，后者把 `fahrenheit` 连接器设置为 77。

**使用约束系统。** 要使用约束系统来完成上面概述的温度计算，我们首先通过调用 `connector` 构造函数创建两个具名连接器 `celsius` 和 `fahrenheit`。

```python
>>> celsius = connector('Celsius')
>>> fahrenheit = connector('Fahrenheit')
```

然后，我们把这些连接器连接成一个与上图对应的网络。函数 `converter` 负责组装网络中的各个连接器和约束。

```python
>>> def converter(c, f):
        """Connect c to f with constraints to convert from Celsius to Fahrenheit."""
        u, v, w, x, y = [connector() for _ in range(5)]
        multiplier(c, w, u)
        multiplier(v, x, u)
        adder(v, y, f)
        constant(w, 9)
        constant(x, 5)
        constant(y, 32)
```

```python
>>> converter(celsius, fahrenheit)
```

我们将使用一个消息传递系统来协调约束与连接器。约束是不自身持有局部状态的字典。它们对消息的响应是改变它们所约束的连接器的非纯函数。

连接器是持有当前值并响应操纵该值的消息的字典。约束不会直接改变连接器的值，而是通过发送消息来做到这一点，这样连接器就能在响应变化时通知其他约束。这样，连接器既表示一个数，又封装了连接器的行为。

我们可以发送给连接器的一条消息是设置它的值。这里，我们（`'user'`）把 `celsius` 的值设置为 25。

```python
>>> celsius['set_val']('user', 25)
Celsius = 25
Fahrenheit = 77.0
```

不仅 `celsius` 的值变为 25，而且它的值会在整个网络中传播，因此 `fahrenheit` 的值也随之改变。这些变化之所以被打印出来，是因为我们在构造这两个连接器时给它们起了名字。

现在，我们试着把 `fahrenheit` 设置为一个新值，比如 212。

```python
>>> fahrenheit['set_val']('user', 212)
Contradiction detected: 77.0 vs 212
```

连接器抱怨它察觉到矛盾：它的值是 77.0，而有人试图把它设置为 212。如果我们真的想用新值重用这个网络，我们可以让 `celsius` 忘记它的旧值：

```python
>>> celsius['forget']('user')
Celsius is forgotten
Fahrenheit is forgotten
```

连接器 `celsius` 发现，最初设置它值的 `user` 现在正在撤回那个值，于是 `celsius` 同意丢失它的值，并把这一事实告知网络其余部分。这一信息最终传播到 `fahrenheit`，后者现在发现自己没有理由继续相信自己的值是 77。因此，它也放弃了自己的值。

既然 `fahrenheit` 没有值了，我们就可以自由地把它设置为 212：

```python
>>> fahrenheit['set_val']('user', 212)
Fahrenheit = 212
Celsius = 100.0
```

这个新值在网络中传播时，迫使 `celsius` 取值 100。我们用完全相同的网络，既根据 `fahrenheit` 计算出了 `celsius`，也根据 `celsius` 计算出了 `fahrenheit`。计算的这种无方向性，正是基于约束的系统的显著特征。

**实现约束系统。** 正如我们已经看到的，连接器是把消息名映射到函数值和数据值的字典。我们将实现响应以下消息的连接器：

- `connector['set_val'](source, value)` 表示 `source` 请求该连接器把当前值设置为 `value`。
- `connector['has_val']()` 返回该连接器是否已经有值。
- `connector['val']` 是该连接器的当前值。
- `connector['forget'](source)` 告知该连接器，`source` 请求它忘记自己的值。
- `connector['connect'](source)` 告知该连接器参与一个新的约束，即 `source`。

约束也是字典，它们通过两条消息从连接器接收信息：

- `constraint['new_val']()` 表示连接到该约束的某个连接器有了新值。
- `constraint['forget']()` 表示连接到该约束的某个连接器忘记了它的值。

当约束接收到这些消息时，它们会适当地把这些消息传播给其他连接器。

`adder` 函数在三个连接器之上构造一个加法器约束，其中前两个必须相加得到第三个：`a + b = c`。为了支持多方向的约束传播，加法器还必须指明它从 `c` 中减去 `a` 得到 `b`，同样从 `c` 中减去 `b` 得到 `a`。

```python
>>> from operator import add, sub
>>> def adder(a, b, c):
        """The constraint that a + b = c."""
        return make_ternary_constraint(a, b, c, add, sub, sub)
```

我们希望实现一个通用的三元（三路）约束，它使用来自 `adder` 的三个连接器和三个函数，创建一个接受 `new_val` 和 `forget` 消息的约束。对这些消息的响应是局部函数，它们被放入一个名为 `constraint` 的字典中。

```python
>>> def make_ternary_constraint(a, b, c, ab, ca, cb):
        """The constraint that ab(a,b)=c and ca(c,a)=b and cb(c,b) = a."""
        def new_value():
            av, bv, cv = [connector['has_val']() for connector in (a, b, c)]
            if av and bv:
                c['set_val'](constraint, ab(a['val'], b['val']))
            elif av and cv:
                b['set_val'](constraint, ca(c['val'], a['val']))
            elif bv and cv:
                a['set_val'](constraint, cb(c['val'], b['val']))
        def forget_value():
            for connector in (a, b, c):
                connector['forget'](constraint)
        constraint = {'new_val': new_value, 'forget': forget_value}
        for connector in (a, b, c):
            connector['connect'](constraint)
        return constraint
```

名为 `constraint` 的这个字典是一个分派字典，同时也是约束对象本身。它响应约束所接收的两条消息，同时也在对其连接器的调用中作为 `source` 参数被传递。

约束的局部函数 `new_value` 会在该约束被通知它的某个连接器有值时被调用。这个函数首先检查 `a` 和 `b` 是否都有值。如果有，它就告诉 `c` 把其值设为函数 `ab` 的返回值，对于 `adder` 而言 `ab` 就是 `add`。该约束把*它自己*（`constraint`）作为连接器的 `source` 参数传递，而这里的连接器就是加法器对象。如果 `a` 和 `b` 并非都有值，那么该约束就检查 `a` 和 `c`，依此类推。

如果该约束被通知它的某个连接器忘记了值，它就请求它的所有连接器现在都忘记各自的值。（只有那些由该约束设置的值才真正会丢失。）

`multiplier` 与 `adder` 非常相似。

```python
>>> from operator import mul, truediv
>>> def multiplier(a, b, c):
        """The constraint that a * b = c."""
        return make_ternary_constraint(a, b, c, mul, truediv, truediv)
```

常量也是一种约束，但它从不接收任何消息，因为它只涉及单个连接器，并在构造时就把它设置好。

```python
>>> def constant(connector, value):
        """The constraint that connector = value."""
        constraint = {}
        connector['set_val'](constraint, value)
        return constraint
```

这三种约束就足以实现我们的温度转换网络了。

**表示连接器。** 连接器被表示为一个字典，它包含一个值，但同时也带有具备局部状态的响应函数。连接器必须跟踪给它当前值的那个 `informant`（告知者），以及一个它参与其中的 `constraints` 列表。

构造函数 `connector` 具有用于设置和忘记值的局部函数，这些函数就是对来自约束的消息的响应。

```python
>>> def connector(name=None):
        """A connector between constraints."""
        informant = None
        constraints = []
        def set_value(source, value):
            nonlocal informant
            val = connector['val']
            if val is None:
                informant, connector['val'] = source, value
                if name is not None:
                    print(name, '=', value)
                inform_all_except(source, 'new_val', constraints)
            else:
                if val != value:
                    print('Contradiction detected:', val, 'vs', value)
        def forget_value(source):
            nonlocal informant
            if informant == source:
                informant, connector['val'] = None, None
                if name is not None:
                    print(name, 'is forgotten')
                inform_all_except(source, 'forget', constraints)
        connector = {'val': None,
                     'set_val': set_value,
                     'forget': forget_value,
                     'has_val': lambda: connector['val'] is not None,
                     'connect': lambda source: constraints.append(source)}
        return connector
```

连接器同样是一个分派字典，用于约束与连接器通信的五条消息。其中四个响应是函数，最后一个响应是值本身。

局部函数 `set_value` 在有人请求设置连接器的值时被调用。如果连接器当前没有值，它就会设置自己的值，并记住请求设置该值的源约束作为 `informant`。然后，连接器会通知它参与的所有约束，但请求设置该值的那个约束除外。这是通过下面的迭代函数完成的。

```python
>>> def inform_all_except(source, message, constraints):
        """Inform all constraints of the message, except source."""
        for c in constraints:
            if c != source:
                c[message]()
```

如果某个连接器被要求忘记它的值，它会调用局部函数 `forget-value`，该函数首先确认这一请求来自最初设置该值的同一个约束。如果是，连接器就把它丢失值这一情况通知其关联的约束。

对消息 `has_val` 的响应表明连接器是否有值。对消息 `connect` 的响应则把源约束添加到约束列表中。

我们设计的这个约束程序引入了许多将在面向对象编程中再次出现的想法。约束和连接器都是通过消息来操纵的抽象。当连接器的值被改变时，它是通过一条消息来改变的，这条消息不仅改变值，还会验证它（检查源）并传播其效果（通知其他约束）。事实上，我们将在本章后面使用一种类似的、以字符串为键、以函数为值的字典架构来实现一个面向对象系统。
