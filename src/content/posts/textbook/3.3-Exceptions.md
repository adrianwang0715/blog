## 3.3   异常

程序员必须始终留意程序中可能出现的各种错误。这样的例子比比皆是：一个函数可能没有收到它设计上期望接收的参数，一个必需的资源可能缺失，或者跨越网络的连接可能中断。在设计程序时，必须预见到可能出现的这些异常（exceptional）情况，并采取适当的措施来处理它们。

处理程序中的错误并没有唯一正确的方法。为提供持久服务（例如 Web 服务器）而设计的程序应当对错误具有鲁棒性，把它们记录下来供日后分析，同时尽可能继续处理新的请求。另一方面，Python 解释器处理错误的方式是立即终止并打印一条错误信息，以便程序员能够在问题出现时马上着手解决。无论如何，程序员都必须有意识地做出选择，决定自己的程序应当如何应对异常情况。

*异常（exception）*，也就是本节的主题，为给程序添加错误处理逻辑提供了一种通用机制。*抛出异常（raising an exception）* 是一种技术，用于中断程序正常的执行流程，表明某个异常情况已经出现，并直接返回到程序中某个被指定用来应对该情况的外围部分。Python 解释器每次在表达式或语句中检测到错误时都会抛出一个异常。用户也可以使用 `raise` 和 `assert` 语句来抛出异常。

**抛出异常。** 异常是一个对象实例，其所属的类直接或间接地继承自 `BaseException` 类。第 1 章中介绍的 `assert` 语句会抛出一个类为 `AssertionError` 的异常。一般来说，任何异常实例都可以通过 `raise` 语句抛出。raise 语句的一般形式在 [Python 文档](http://docs.python.org/py3k/reference/simple_stmts.html#raise)中有描述。`raise` 最常见的用法是构造一个异常实例并将其抛出。

```python
>>> raise Exception('An error occurred')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
Exception: an error occurred
```

当异常被抛出时，当前代码块中后续的语句都不会再执行。除非该异常被*捕获（handled）*（下文会介绍），否则解释器会直接返回到交互式读取-求值-打印循环，或者如果 Python 是以文件参数启动的，则完全终止。此外，解释器还会打印一份*栈回溯（stack backtrace）*，这是一段结构化的文本，描述了抛出异常的那条执行分支中嵌套的活动函数调用集合。在上面的例子中，文件名 `<stdin>` 表明该异常是用户在交互式会话中抛出的，而不是来自文件中的代码。

**捕获异常。** 异常可以由外层的一个 `try` 语句捕获。一个 `try` 语句由多个子句组成；第一个以 `try` 开头，其余的以 `except` 开头：

```python
try:
    <try suite>
except <exception class> as <name>:
    <except suite>
...
```

`<try suite>` 在 `try` 语句执行时总是会立即执行。`except` 子句的套件只有在执行 `<try suite>` 的过程中抛出了异常时才会执行。每个 `except` 子句都指定了它要处理的特定异常类。例如，如果 `<exception class>` 是 `AssertionError`，那么在执行 `<try suite>` 的过程中抛出的任何继承自 `AssertionError` 的类的实例，都将由随后的 `<except suite>` 处理。在 `<except suite>` 内部，标识符 `<name>` 被绑定到被抛出的那个异常对象上，但这种绑定不会持续到 `<except suite>` 之外。

例如，我们可以用一个 `try` 语句来处理 `ZeroDivisionError` 异常，在异常被抛出时把名字 `x` 绑定为 0。

```python
>>> try:
        x = 1/0
    except ZeroDivisionError as e:
        print('handling a', type(e))
        x = 0
handling a <class 'ZeroDivisionError'>
>>> x
0
```

`try` 语句会处理那些发生在 `<try suite>` 中被应用（直接或间接应用）的函数体内的异常。当异常被抛出时，控制权会直接跳到最近的那个能处理该类型异常的 `try` 语句的 `<except suite>` 函数体中。

```python
>>> def invert(x):
        result = 1/x  # Raises a ZeroDivisionError if x is 0
        print('Never printed if x is 0')
        return result
```

```python
>>> def invert_safe(x):
        try:
            return invert(x)
        except ZeroDivisionError as e:
            return str(e)
```

```python
>>> invert_safe(2)
Never printed if x is 0
0.5
>>> invert_safe(0)
'division by zero'
```

这个例子说明，`invert` 中的 `print` 表达式从未被求值，控制权反而被转移到了 `invert_safe` 中 `except` 子句的套件。把 `ZeroDivisionError` 实例 `e` 强制转换为字符串，就得到了 `invert_safe` 返回的、人类可读的字符串：`'division by zero'`。

### 3.3.1   异常对象

异常对象本身可以带有属性，例如 `assert` 语句中声明的错误信息，以及关于异常是在执行过程中何处被抛出的信息。用户自定义的异常类还可以有额外的属性。

在第 1 章中，我们实现了牛顿法来求任意函数的零点。下面的例子定义了一个异常类，它在发生 `ValueError` 时返回迭代改进过程中发现的最佳猜测值。当 `sqrt` 被应用于一个负数时会抛出数学定义域错误（一种 `ValueError`）。这个异常通过抛出一个 `IterImproveError` 来处理，该异常把牛顿法最近一次的猜测值存为一个属性。

首先，我们定义一个新类，它继承自 `Exception`。

```python
>>> class IterImproveError(Exception):
        def __init__(self, last_guess):
            self.last_guess = last_guess
```

接下来，我们定义 `improve` 的一个版本，也就是我们的通用迭代改进算法。这个版本通过抛出一个 `IterImproveError` 来处理任何 `ValueError`，该异常会保存最近一次的猜测值。和之前一样，`improve` 接受两个函数作为参数，每个函数都接受一个数值参数。`update` 函数返回新的猜测值，而 `done` 函数返回一个布尔值，表示改进是否已经收敛到正确的值。

```python
>>> def improve(update, done, guess=1, max_updates=1000):
        k = 0
        try:
            while not done(guess) and k < max_updates:
                guess = update(guess)
                k = k + 1
            return guess
        except ValueError:
            raise IterImproveError(guess)
```

最后，我们定义 `find_zero`，它返回把 `improve` 应用于 `newton_update` 所返回的牛顿更新函数之后的结果——`newton_update` 定义在第 1 章，在这个例子中无需任何改动。这个版本的 `find_zero` 通过返回其最后一次猜测值来处理 `IterImproveError`。

```python
>>> def find_zero(f, guess=1):
        def done(x):
            return f(x) == 0
        try:
            return improve(newton_update(f), done, guess)
        except IterImproveError as e:
            return e.last_guess
```

考虑用 `find_zero` 来求函数 $2x^2 + \sqrt{x}$ 的零点。这个函数在 0 处有一个零点，但对任何负数求值都会抛出一个 `ValueError`。我们在第 1 章中实现的牛顿法会抛出这个错误，从而无法返回任何关于零点的猜测值。我们修改后的实现则会返回在错误出现之前找到的最后一次猜测值。

```python
>>> from math import sqrt
>>> find_zero(lambda x: 2*x*x + sqrt(x))
-0.030211203830201594
```

尽管这个近似值距离正确答案 0 仍然很远，但有些应用更愿意接受这种粗略的近似，而不是一个 `ValueError`。

异常是另一种帮助我们把这些程序的关注点分离成模块化部分的技术。在这个例子中，Python 的异常机制让我们得以把迭代改进的逻辑（它在 `try` 子句的套件中保持不变）与错误处理的逻辑（它出现在 `except` 子句中）分离开来。我们还会发现，在 Python 中实现解释器时，异常也是一个很有用的特性。
