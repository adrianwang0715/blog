## 4.3   声明式编程

除了流（stream）之外，数据值还常常存储在称为数据库（database）的大型仓库中。数据库由两部分组成：一个存储结构化数据值的数据存储，以及一个用于根据数据特征检索其子集的接口。数据库中存储的每一个值称为一条*记录（record）*。记录通常通过*查询（query）*来检索，查询是查询编程语言中的一种表达式。迄今为止，当今使用最普遍的查询语言叫作结构化查询语言（Structured Query Language），即 SQL（读音为 "sequel"）。

SQL 是声明式编程（declarative programming）语言的一个例子。表达式并不直接描述计算过程，而是陈述某种计算结果的形态。设计和执行计算过程以产生这样的结果，是数据库系统中*查询解释器（query interpreter）*的职责。

这种交互方式与 Python 或 Scheme 的过程式编程范式有本质区别。在 Python 中，计算过程由程序员直接描述。而声明式语言只规定结果的形态，把过程性的细节抽象掉。

在本节中，我们介绍一种专为本书设计的声明式查询语言，称为 `logic`。它基于 [Prolog](http://en.wikipedia.org/wiki/Prolog) 以及[《计算机程序的构造和解释》](http://mitpress.mit.edu/sicp/full-text/book/book-Z-H-29.html#%_sec_4.4.1)中的声明式语言。数据记录表示为 Scheme 列表，查询表示为 Scheme 值。[logic](http://composingprograms.com/examples/logic/logic.py.html) 是一个完整的实现，它依赖于上一章的 Scheme 项目。

### 4.3.1   事实与查询

数据库存储代表系统中事实（fact）的记录。查询解释器的用途是检索直接从数据库记录中取出的事实集合，同时利用逻辑推理从数据库中推导出新的事实。`logic` 语言中的 `fact` 语句由关键字 `fact` 之后的一个或多个列表组成。一个简单的事实就是单个列表。一位对美国历任总统感兴趣的养狗人可以用 `logic` 语言记录她所养狗只的谱系，如下所示：

```scheme
logic> (fact (parent abraham barack))
logic> (fact (parent abraham clinton))
logic> (fact (parent delano herbert))
logic> (fact (parent fillmore abraham))
logic> (fact (parent fillmore delano))
logic> (fact (parent fillmore grover))
logic> (fact (parent eisenhower fillmore))
```

每个事实都不是像 Scheme 表达式那样的过程调用，而是一个被声明出来的*关系（relation）*。"狗 Abraham 是 Barack 的父/母"，这就是第一个事实所声明的内容。关系类型不需要事先定义。关系并不被调用，而是与查询进行匹配。

查询同样由一个或多个列表组成，但以关键字 `query` 开头。查询可以包含变量，变量是以问号开头的符号。变量由查询解释器匹配到事实：

```scheme
logic> (query (parent abraham ?child))
Success!
child: barack
child: clinton
```

查询解释器以 `Success!` 作为响应，表示该查询匹配到了某些事实。接下来的几行显示了变量 `?child` 的各个取值，它们使查询与数据库中的事实相匹配。

**复合事实。** 事实也可以包含变量以及多个子表达式。多表达式的事实以一个结论开头，其后是若干假设（hypothesis）。要使结论为真，所有的假设都必须得到满足：

```scheme
(fact <conclusion> <hypothesis0> <hypothesis1> ... <hypothesisN>)
```

例如，可以根据数据库中已有的关于父/母的事实，声明关于子女的事实：

```scheme
logic> (fact (child ?c ?p) (parent ?p ?c))
```

上述事实可以读作："只要 `?p` 是 `?c` 的父/母，那么 `?c` 就是 `?p` 的子女。"现在查询可以引用这个事实：

```scheme
logic> (query (child ?child fillmore))
Success!
child: abraham
child: delano
child: grover
```

上面的查询要求查询解释器把定义 `child` 的那个事实与关于 `fillmore` 的各种 parent 事实结合起来。该语言的用户不需要知道这些信息是如何结合的，只需要知道结果具有特定的形态。证明 `(child abraham fillmore)` 在已有事实下为真，是查询解释器的职责。

查询并非必须包含变量；它也可以只是验证一个事实：

```scheme
logic> (query (child herbert delano))
Success!
```

一个不匹配任何事实的查询将返回失败：

```scheme
logic> (query (child eisenhower ?parent))
Failure.
```

### 4.3.2   递归事实

`logic` 语言也允许递归事实。也就是说，一个事实的结论可以依赖于包含相同符号的假设。例如，ancestor 关系由两个事实定义。若某个 `?a` 是 `?y` 的父/母，或者它是 `?y` 的某个祖先的父/母，则 `?a` 是 `?y` 的祖先：

```scheme
logic> (fact (ancestor ?a ?y) (parent ?a ?y))
logic> (fact (ancestor ?a ?y) (parent ?a ?z) (ancestor ?z ?y))
```

随后，单个查询就可以列出 `herbert` 的所有祖先：

```scheme
logic> (query (ancestor ?a herbert))
Success!
a: delano
a: fillmore
a: eisenhower
```

**复合查询。** 一个查询可以有多个子表达式，此时所有这些子表达式都必须同时被一组符号到变量的赋值所满足。如果一个变量在查询中出现多次，那么它在每个上下文中都必须取相同的值。下面的查询找出同时是 `herbert` 和 `barack` 的祖先者：

```scheme
logic> (query (ancestor ?a barack) (ancestor ?a herbert))
Success!
a: fillmore
a: eisenhower
```

递归事实可能需要很长的推理链条，才能把查询与数据库中已有的事实匹配起来。例如，要证明事实 `(ancestor fillmore herbert)`，我们必须依次证明以下各个事实：

```scheme
(parent delano herbert)       ; (1), a simple fact
(ancestor delano herbert)     ; (2), from (1) and the 1st ancestor fact
(parent fillmore delano)      ; (3), a simple fact
(ancestor fillmore herbert)   ; (4), from (2), (3), & the 2nd ancestor fact
```

这样一来，只要查询解释器能够发现它们，单个事实就可以蕴含大量额外的事实，甚至是无穷多个事实。

**层次化事实。** 到目前为止，每个事实和查询表达式都是符号的列表。此外，事实和查询的列表还可以包含列表，从而提供了一种表示层次化数据的方式。每只狗的颜色可以随名字一起存储为一条额外的记录：

```scheme
logic> (fact (dog (name abraham) (color white)))
logic> (fact (dog (name barack) (color tan)))
logic> (fact (dog (name clinton) (color white)))
logic> (fact (dog (name delano) (color white)))
logic> (fact (dog (name eisenhower) (color tan)))
logic> (fact (dog (name fillmore) (color brown)))
logic> (fact (dog (name grover) (color tan)))
logic> (fact (dog (name herbert) (color brown)))
```

查询既可以完整地表述层次化事实的结构，也可以把变量匹配到整个列表：

```scheme
logic> (query (dog (name clinton) (color ?color)))
Success!
color: white

logic> (query (dog (name clinton) ?info))
Success!
info: (color white)
```

数据库的强大之处很大程度上在于，查询解释器能够在单个查询中把多种事实联结（join）起来。下面的查询找出所有这样一对狗：其中一只是另一只的祖先，并且它们颜色相同：

```scheme
logic> (query (dog (name ?name) (color ?color))
              (ancestor ?ancestor ?name)
              (dog (name ?ancestor) (color ?color)))
Success!
name: barack    color: tan      ancestor: eisenhower
name: clinton   color: white    ancestor: abraham
name: grover    color: tan      ancestor: eisenhower
name: herbert   color: brown    ancestor: fillmore
```

在层次化记录中，变量既可以引用列表，也可以使用点记法（dot notation）。位于点之后的变量匹配事实中列表的其余部分。带点的列表可以出现在事实或查询中。下面的例子通过列出祖先链来构造狗的谱系。年轻的 `barack` 承袭了一条可敬的总统犬血脉：

```scheme
logic> (fact (pedigree ?name) (dog (name ?name) . ?details))
logic> (fact (pedigree ?child ?parent . ?rest)
             (parent ?parent ?child)
             (pedigree ?parent . ?rest))

logic> (query (pedigree barack . ?lineage))
Success!
lineage: ()
lineage: (abraham)
lineage: (abraham fillmore)
lineage: (abraham fillmore eisenhower)
```

声明式编程或逻辑编程能够以惊人的效率表达事实之间的关系。例如，如果我们想表达两个列表可以拼接成一个更长的列表——其元素先是第一个列表的元素，随后是第二个列表的元素——我们只需声明两条规则。首先，一个基础情形声明：把空列表拼接到任何列表上得到的仍是那个列表：

```scheme
logic> (fact (append-to-form () ?x ?x))
```

其次，一条递归事实声明：一个首元素为 `?a`、其余部分为 `?r` 的列表，与列表 `?y` 拼接后，形成首元素为 `?a`、其余部分为某个拼接结果 `?z` 的列表。要使这一关系成立，必须满足 `?r` 与 `?y` 拼接后形成 `?z`：

```scheme
logic> (fact (append-to-form (?a . ?r) ?y (?a . ?z)) (append-to-form ?r ?y ?z))
```

利用这两个事实，查询解释器可以计算任意两个列表拼接的结果：

```scheme
logic> (query (append-to-form (a b c) (d e) ?result))
Success!
result: (a b c d e)
```

此外，它还能计算出所有可能的列表对 `?left` 和 `?right`，使它们拼接后形成列表 `(a b c d e)`：

```scheme
logic> (query (append-to-form ?left ?right (a b c d e)))
Success!
left: ()  right: (a b c d e)
left: (a) right: (b c d e)
left: (a b)   right: (c d e)
left: (a b c) right: (d e)
left: (a b c d)   right: (e)
left: (a b c d e) right: ()
```

尽管我们的查询解释器看起来相当智能，但我们将会看到，它是通过反复执行一个简单操作来找出这些组合的：在一个环境中匹配两个含有变量的列表。
