## 2.8   泛型操作

在本章中，我们介绍了复合数据值，以及使用构造函数和选择函数的数据抽象技术。借助于消息传递，我们直接把行为赋予了我们的抽象数据类型。借助于对象隐喻，我们把数据的表示和用于操作这些数据的方法捆绑在一起，从而用局部状态将数据驱动的程序模块化。

然而，我们尚未说明我们的对象系统如何让我们在大型程序中灵活地把不同类型的对象组合起来。通过点表达式的消息传递，只是用多个对象构建组合表达式的一种方式。在本节中，我们探索组合和操作不同类型对象的其他方法。

### 2.8.1   字符串转换

我们在本章开头说过，一个对象值的行为应当像它所要表示的那种数据，包括生成自身的字符串表示。数据值的字符串表示在像 Python 这样的交互式语言中尤其重要，因为 `read-eval-print` 循环要求每个值都具有某种字符串表示。

字符串值为人与人之间交流信息提供了一种基本媒介。字符序列可以呈现在屏幕上、打印到纸上、朗读出来、转换成盲文，或者以摩尔斯电码广播出去。字符串对编程来说也是基本的，因为它们可以表示 Python 表达式。对于一个对象，我们可能想生成一个字符串，当它被解释为一个 Python 表达式时，求值得到一个等价的**对象**。

Python 规定所有对象都应生成两种不同的字符串表示：一种是人类可解释的文本，另一种是 Python 可解释的表达式。字符串的构造函数 `str` 返回一个人类可读的字符串。在可能的情况下，`repr` 函数返回一个求值后得到相等对象的 Python 表达式。*repr* 的文档字符串解释了这一性质：

```python
repr(object) -> string

Return the canonical string representation of the object.
For most object types, eval(repr(object)) == object.
```

对一个表达式的值调用 `repr` 所得到的结果，就是 Python 在交互式会话中打印出来的内容。

```python
>>> 12e12
12000000000000.0
>>> print(repr(12e12))
12000000000000.0
```

在不存在能够求值得到原值的表示的情况下，Python 会生成一个替代表示。

```python
>>> repr(min)
'<built-in function min>'
```

`str` 构造函数常常与 `repr` 一致，但在某些情况下提供了更易解释的文本表示。例如，我们会在日期上看到 `str` 与 `repr` 之间的差异。

```python
>>> from datetime import date
>>> today = date(2011, 9, 12)
>>> repr(today)
'datetime.date(2011, 9, 12)'
>>> str(today)
'2011-09-12'
```

定义 `repr` 函数带来了一个新的挑战：我们希望它正确地适用于所有数据类型，甚至是那些在 `repr` 被实现时还不存在的数据类型。我们希望它是一个*多态函数*（polymorphic function），即可以应用于许多（*poly*）不同形式（*morph*）的数据。

在这种情况下，消息传递提供了一个优雅的解决方案：`repr` 函数调用其参数上一个名为 `__repr__` 的方法。

```python
>>> today.__repr__()
'datetime.date(2011, 9, 12)'
```

通过在用户定义的类中实现这同一个方法，我们可以把 `repr` 的适用范围扩展到我们将来创建的任何类。这个例子总体上凸显了消息传递的另一个好处，即它提供了一种机制，把既有函数的定义域扩展到新的对象类型。

`str` 构造函数以类似的方式实现：它调用其参数上一个名为 `__str__` 的方法。

```python
>>> today.__str__()
'2011-09-12'
```

这些多态函数是一个更普遍原则的实例：某些函数应当适用于多种数据类型。这里所举例的消息传递方法，只是实现多态函数的一系列技术之一。本节剩余部分将探索一些替代方案。

### 2.8.2   多种表示

使用对象或函数的数据抽象，是管理复杂性的一种强大工具。抽象数据类型允许我们在数据的底层表示与用于操作它的函数或消息之间构造一道抽象屏障。然而，在大型程序中，谈论一个数据类型的"底层表示"并不总是有意义。一方面，一个数据对象可能有不止一种有用的表示，而我们可能想要设计能够处理多种表示的系统。

举一个简单的例子，复数可以用两种几乎等价的方式表示：直角坐标形式（实部和虚部）和极坐标形式（模和幅角）。有时直角坐标形式更合适，有时极坐标形式更合适。事实上，完全有理由设想这样一个系统：复数同时用两种方式表示，而操作复数的函数可以用其中任何一种表示来工作。

更重要的是，大型软件系统常常由许多人在很长一段时间内共同设计，并且要受制于随时间变化的需求。在这样的环境中，让所有人事先就数据表示的选择达成一致根本不可能。除了把表示与使用隔离开来的数据抽象屏障之外，我们还需要把不同的设计选择彼此隔离开来、并允许多种不同选择共存于同一程序中的抽象屏障。此外，由于大型程序常常是通过组合若干**孤立**设计的既有模块而创建的，我们需要一些约定，让程序员能够以增量方式把模块纳入更大的系统，也就是说，无需重新设计或重新实现这些模块。

我们从简单的复数例子开始。我们将看到，消息传递如何让我们为复数分别设计直角坐标表示和极坐标表示，同时保持一个抽象的"复数"对象这一概念。我们将通过用泛型选择函数来定义复数的算术函数（`add_complex`、`mul_complex`）来实现这一点，这些选择函数访问一个复数的各个部分，而与这个数如何表示无关。由此得到的复数系统包含两种不同的抽象屏障。它们把更高层的操作与更低层的表示隔离开来。此外，还有一道垂直屏障，让我们能够分别设计不同的替代表示。

![figure](../img/interface.png)

顺带一提，我们正在开发一个对复数执行算术运算的系统，作为使用泛型操作的、简单但不现实的示例程序。实际上 Python 内置了[复数类型](http://docs.python.org/py3k/library/stdtypes.html#typesnumeric)，但在这个例子中我们将实现自己的复数。

与有理数一样，复数自然地表示为数对。复数集可以看作一个具有两条正交轴（实轴和虚轴）的二维空间。从这个角度看，复数 `z = x + y * i`（其中 `i*i = -1`）可以看作平面上的点，它的实坐标为 `x`，虚坐标为 `y`。复数相加就是把它们各自的 `x` 和 `y` 坐标相加。

在乘法复数时，从极坐标形式来思考更为自然，即把它看成一个模和一个幅角。两个复数的乘积，就是把一个复数按另一个复数的长度拉伸，然后再旋转另一个复数的幅角所得到的向量。

因此，复数有两种不同的表示，它们分别适合不同的操作。然而，从编写使用复数的程序的人的角度来看，数据抽象原则表明，无论计算机使用哪种表示，所有用于操作复数的操作都应当是可用。

**接口。** 消息传递不仅提供了一种把行为和数据耦合起来的方法，它还允许不同的数据类型以不同的方式响应同一条消息。一组共享的、能从不同对象类引出相似行为的消息，是一种强大的抽象方法。

一个*接口*（interface）是一组共享的消息，以及对它们如何行为的说明。响应特殊方法 `__repr__` 和 `__str__` 的对象，都实现了一个共同的接口，即那些可以表示为字符串的类型所构成的接口。

在复数的情况下，实现算术所需的接口由四条消息组成：`real`、`imag`、`magnitude` 和 `angle`。我们可以用这些消息来实现加法和乘法。

我们可以为复数设置两种不同的抽象数据类型，它们在构造函数上有所不同。

- `ComplexRI` 从实部和虚部构造一个复数。
- `ComplexMA` 从一个模和幅角构造一个复数。

有了这些消息和构造函数，我们就可以实现复数算术。

```python
>>> def add_complex(z1, z2):
        return ComplexRI(z1.real + z2.real, z1.imag + z2.imag)
```

```python
>>> def mul_complex(z1, z2):
        return ComplexMA(z1.magnitude * z2.magnitude, z1.angle + z2.angle)
```

"抽象数据类型"（ADT）与"接口"这两个术语之间的关系是微妙的。一个 ADT 包含构建复杂数据类型、把它们作为单元来操作，以及选取其组成部分的方式。在面向对象的系统中，一个 ADT 对应于一个类，尽管我们已经看到，实现一个 ADT 并不需要对象系统。接口是一组带有相关含义的消息，它可能包含也可能不包含选择函数。从概念上说，一个 ADT 描述了某类事物的完整表示抽象，而一个接口则规定了一组可能被许多事物共享的行为。

**属性。** 我们希望可以互换地使用两种类型的复数，但如果为每个数存储冗余信息就太浪费了。我们想只存储实部—虚部表示或者模—幅角表示中的一种。

Python 有一个简单的特性，可以从零参数函数即时计算属性。`@property` 装饰器允许函数在没有标准调用表达式语法的情况下被调用。用实部和虚部实现复数就说明了这一点。

```python
>>> from math import atan2
>>> class ComplexRI(object):
        def __init__(self, real, imag):
            self.real = real
            self.imag = imag
        @property
        def magnitude(self):
            return (self.real ** 2 + self.imag ** 2) ** 0.5
        @property
        def angle(self):
            return atan2(self.imag, self.real)
        def __repr__(self):
            return 'ComplexRI({0}, {1})'.format(self.real, self.imag)
```

使用模和幅角的第二种实现提供了相同的接口，因为它响应同一组消息。

```python
>>> from math import sin, cos
>>> class ComplexMA(object):
        def __init__(self, magnitude, angle):
            self.magnitude = magnitude
            self.angle = angle
        @property
        def real(self):
            return self.magnitude * cos(self.angle)
        @property
        def imag(self):
            return self.magnitude * sin(self.angle)
        def __repr__(self):
            return 'ComplexMA({0}, {1})'.format(self.magnitude, self.angle)
```

事实上，我们对 `add_complex` 和 `mul_complex` 的实现现在已经是完整的了；两种复数的类都可以用于任一复数算术函数中的任一参数。值得注意的是，对象系统并没有以任何方式（例如通过继承）显式地把这两个复数类型连接起来。我们是通过在两个类之间共享一组共同的消息（一个接口）来实现复数抽象的。

```python
>>> from math import pi
>>> add_complex(ComplexRI(1, 2), ComplexMA(2, pi/2))
ComplexRI(1.0000000000000002, 4.0)
>>> mul_complex(ComplexRI(0, 1), ComplexRI(0, 1))
ComplexMA(1.0, 3.141592653589793)
```

用接口方法来编码多种表示具有吸引人的性质。每种表示的类可以单独开发；它们只需在彼此共享的属性名上达成一致。接口也是*可增量的*。如果另一位程序员想向同一个程序添加复数的第三种表示，他们只需创建另一个具有相同属性的类即可。

### 2.8.3   特殊方法

内置的数学运算符可以像 `repr` 那样被扩展；对于算术、逻辑和序列操作，都有与 Python 运算符相对应的特殊方法名。

为了让代码更易读，我们也许希望在对复数进行加法和乘法时直接使用 `+` 和 `*` 运算符。向我们的两个复数类都添加下列方法，就能使用这些运算符，也能使用 `operator` 模块中的 `add` 和 `mul` 函数：

```python
>>> ComplexRI.__add__ = lambda self, other: add_complex(self, other)
>>> ComplexMA.__add__ = lambda self, other: add_complex(self, other)
>>> ComplexRI.__mul__ = lambda self, other: mul_complex(self, other)
>>> ComplexMA.__mul__ = lambda self, other: mul_complex(self, other)
```

现在，我们可以在用户定义的类上使用中缀记法了。

```python
>>> ComplexRI(1, 2) + ComplexMA(2, 0)
ComplexRI(3.0, 2.0)
>>> ComplexRI(0, 1) * ComplexRI(0, 1)
ComplexMA(1.0, 3.141592653589793)
```

**真值与假值。** 我们之前看到，Python 中的数字具有真值；更具体地说，0 是假值，其他所有数字都是真值。事实上，Python 中所有对象都具有真值。默认情况下，对象被视为真值，但特殊方法 `__bool__` 可以用来覆盖这一行为。如果一个对象定义了 `__bool__` 方法，那么 Python 会调用该方法来确定它的真值。

举个例子，假设我们希望复数 `0 + 0 * i` 为假。我们可以为两种复数实现都定义 `__bool__` 方法。

```python
>>> ComplexRI.__bool__ = lambda self: self.real != 0 or self.imag != 0
>>> ComplexMA.__bool__ = lambda self: self.magnitude != 0
```

我们可以调用 `bool` 构造函数来查看一个对象的真值，也可以在布尔上下文中使用任何对象。

```python
>>> bool(ComplexRI(1, 2))
True
>>> bool(ComplexRI(0, 0))
False
>>> if not ComplexMA(0, 1):
        print("complex number is true")
complex number is true
```

**序列长度。** 我们已经看到，可以调用 `len` 函数来确定一个序列的长度。

```python
>>> len('Go Bears!')
9
```

`len` 函数调用其参数的 `__len__` 方法来确定其长度。所有内置序列类型都实现了这个方法。

```python
>>> 'Go Bears!'.__len__()
9
```

如果一个序列没有提供 `__bool__` 方法，Python 就用它的长度来确定其真值。空序列为假，而非空序列为真。

```python
>>> bool('')
False
>>> bool([])
False
>>> bool('Go Bears!')
True
```

**可调用对象。** 在 Python 中，函数是一等对象，因此它们可以像数据一样被传递，并且像任何其他对象一样拥有属性。Python 还允许我们通过包含一个 `__call__` 方法来定义可以像函数一样被"调用"的对象。有了这个方法，我们就可以定义一个行为类似于高阶函数的类。

举个例子，考虑下面的高阶函数，它返回一个把常数值加到其参数上的函数。

```python
>>> def make_adder(n):
        def adder(k):
            return n + k
        return adder
```

```python
>>> add_three = make_adder(3)
>>> add_three(4)
7
```

我们可以创建一个定义 `__call__` 方法的 `Adder` 类，来提供相同的功能。

```python
>>> class Adder(object):
        def __init__(self, n):
            self.n = n
        def __call__(self, k):
            return self.n + k
```

```python
>>> add_three_obj = Adder(3)
>>> add_three_obj(4)
7
```

在这里，`Adder` 类的行为类似于 `make_adder` 高阶函数，而 `add_three_obj` 对象的行为类似于 `add_three` 函数。我们进一步模糊了数据与函数之间的界线。

尽管可调用对象比高阶函数效率低，但它们让我们能够充分利用对象系统。例如，我们可以用继承来创建一族共享功能的可调用对象。

**延伸阅读。** 特殊方法把内置运算符一般化，使它们能够用于用户定义的对象。为了提供这种一般性，Python 遵循特定的协议来应用每一个运算符。例如，为了求值包含 `+` 运算符的表达式，Python 会检查表达式左操作数和右操作数上的特殊方法。首先，Python 在左操作数的值上检查 `__add__` 方法，然后在右操作数的值上检查 `__radd__` 方法。如果找到其中任何一个，就会以另一个操作数的值作为参数调用该方法。

对于求值 Python 中任何类型的运算符（包括切片记法和布尔运算符）的表达式，也存在类似的协议。Python 文档列出了完备的[运算符方法名集合](http://docs.python.org/py3k/reference/datamodel.html#special-method-names)。Dive into Python 3 有一章讲述[特殊方法名](http://getpython3.com/diveintopython3/special-method-names.html)，描述了它们在 Python 解释器中使用的大量细节。

### 2.8.4   泛型函数

我们对复数的实现使两个数据类型在作为 `add_complex` 和 `mul_complex` 函数的参数时可以互换。现在我们将看到，如何使用这同一个想法，不仅定义对多种表示具有一般性的操作，还定义对不同种类的、不共享共同接口的参数也具有一般性的操作。

到目前为止我们所定义的操作把不同的数据类型视为完全独立。因此，对于把两个有理数相加，或者把两个复数相加，存在着彼此独立的代码包。我们尚未考虑到这样一个事实：定义跨越类型边界的操作是有意义的，例如把一个复数与一个有理数相加。我们费了很大力气在程序各部分之间引入屏障，以便它们可以被分别开发和理解。

我们希望以某种仔细控制的、不严重违反抽象边界的方式来引入跨类型操作。在我们想要的结果之间存在一种张力：我们希望能够把一个复数与一个有理数相加，并且希望用一个对**所有**数值类型都能正确处理的泛型 `add` 函数来做到这一点。与此同时，我们希望尽可能把复数与有理数的关注点分离开来，以保持程序的模块化。

让我们修订有理数的实现，改用 Python 内置的对象系统。和之前一样，我们将把一个有理数存储为最简形式的分子和分母。

```python
>>> from fractions import gcd
>>> class Rational(object):
        def __init__(self, numer, denom):
            g = gcd(numer, denom)
            self.numer = numer // g
            self.denom = denom // g
        def __repr__(self):
            return 'Rational({0}, {1})'.format(self.numer, self.denom)
```

在这个新实现中对有理数进行加法和乘法与之前类似。

```python
>>> def add_rationals(x, y):
        nx, dx = x.numer, x.denom
        ny, dy = y.numer, y.denom
        return Rational(nx * dy + ny * dx, dx * dy)
```

```python
>>> def mul_rationals(x, y):
        return Rational(x.numer * y.numer, x.denom * y.denom)
```

**类型分派。** 处理跨类型操作的一种方式，是为该操作有效的每一种可能的类型组合设计一个不同的函数。例如，我们可以扩展复数实现，使它提供一个把复数与有理数相加的函数。我们可以用一种称为*按类型分派*（dispatching on type）的技术来一般性地提供这一功能。

类型分派（type dispatching）的思想是编写这样的函数：它先检查所收到参数的类型，然后执行适合该类型的代码。在 Python 中，可以用内置的 `type` 函数检查一个对象的类型。

```python
>>> def complex(z):
        return type(z) in (ComplexRI, ComplexMA)
```

```python
>>> def rational(z):
        return type(z) == Rational
```

在这种情况下，我们依赖这样一个事实：每个对象都知道自己的类型，而我们可以用 Python 的 `type` 函数查出该类型。即使 `type` 函数不可用，我们也可以借助 `Rational`、`ComplexRI` 和 `ComplexMA` 共享的类属性来实现 `complex` 和 `rational` 函数。

现在考虑下面这个 `add` 实现，它显式检查两个参数的类型。在这个例子中我们不会使用 Python 的特殊方法（即 `__add__`）。

```python
>>> def add_complex_and_rational(z, r):
        return ComplexRI(z.real + r.numer/r.denom, z.imag)
```

```python
>>> def add(z1, z2):
        """Add z1 and z2, which may be complex or rational."""
        if complex(z1) and complex(z2):
            return add_complex(z1, z2)
        elif complex(z1) and rational(z2):
            return add_complex_and_rational(z1, z2)
        elif rational(z1) and complex(z2):
            return add_complex_and_rational(z2, z1)
        else:
            return add_rationals(z1, z2)
```

这种使用大型条件语句的、过于简单的类型分派方式不是可增量的。如果程序中要加入另一种数值类型，我们就必须用新的分支重新实现 `add`。

我们可以通过字典来实现类型分派，从而创建 `add` 的一个更灵活的实现。扩展 `add` 灵活性的第一步，是为我们的类创建一个标签集合，把两种复数实现的差异抽象掉。

```python
>>> def type_tag(x):
        return type_tags[type(x)]
```

```python
>>> type_tags = {ComplexRI: 'com', ComplexMA: 'com', Rational: 'rat'}
```

我们可以把这些类型标签用作存储不同加法方式的字典的键。该字典的键是类型标签组成的元组，值是特定于类型的加法函数。

```python
>>> def add(z1, z2):
        types = (type_tag(z1), type_tag(z2))
        return add_implementations[types](z1, z2)
```

这个 `add` 定义本身没有任何功能；它完全依赖一个名为 `add_implementations` 的字典来实现加法。我们可以像下面这样填充那个字典。

```python
>>> add_implementations = {}
>>> add_implementations[('com', 'com')] = add_complex
>>> add_implementations[('com', 'rat')] = add_complex_and_rational
>>> add_implementations[('rat', 'com')] = lambda x, y: add_complex_and_rational(y, x)
>>> add_implementations[('rat', 'rat')] = add_rationals
```

这种基于字典的分派方式是可扩展的，因为随着系统中实现新的数值类型，可以向 `add_implementations` 和 `type_tags` 中加入新的条目。

虽然我们给系统引入了一些复杂性，但我们现在有了一个能处理混合类型的泛型 `add` 函数。

```python
>>> add(ComplexRI(1.5, 0), Rational(3, 2))
ComplexRI(3.0, 0)
>>> add(Rational(5, 3), Rational(1, 2))
Rational(13, 6)
```

**数据导向编程。** 我们基于字典的 `add` 实现根本就不是特定于加法的；它不包含任何直接的加法逻辑。它之所以实现加法，只是因为恰好用执行加法的函数填充了它的 `implementations` 字典。

一个更一般的泛型算术版本，会把任意运算符应用于任意类型，并用一个字典来存储各种组合的实现。这种实现方法的完全泛型方式称为*数据导向编程*（data-directed programming）。在我们的情形中，我们可以实现泛型的加法和乘法，而不带任何冗余逻辑。

```python
>>> def apply(operator_name, x, y):
        tags = (type_tag(x), type_tag(y))
        key = (operator_name, tags)
        return apply_implementations[key](x, y)
```

在这个泛型 `apply` 函数中，键由运算符名（例如 `'add'`）和参数的类型标签组成的元组构造而成。实现也使用这些标签来填充。下面我们为复数和有理数启用对乘法的支持。

```python
>>> def mul_complex_and_rational(z, r):
        return ComplexMA(z.magnitude * r.numer / r.denom, z.angle)
```

```python
>>> mul_rational_and_complex = lambda r, z: mul_complex_and_rational(z, r)
>>> apply_implementations = {('mul', ('com', 'com')): mul_complex,
                             ('mul', ('com', 'rat')): mul_complex_and_rational,
                             ('mul', ('rat', 'com')): mul_rational_and_complex,
                             ('mul', ('rat', 'rat')): mul_rationals}
```

我们还可以用字典的 `update` 方法，把 `add` 中的加法实现也加入 `apply`。

```python
>>> adders = add.implementations.items()
>>> apply_implementations.update({('add', tags):fn for (tags, fn) in adders})
```

现在 apply 在单个字典中支持 8 种不同的实现，我们可以用它相当一般地操作有理数和复数。

```python
>>> apply('add', ComplexRI(1.5, 0), Rational(3, 2))
ComplexRI(3.0, 0)
>>> apply('mul', Rational(1, 2), ComplexMA(10, 1))
ComplexMA(5.0, 1)
```

这种数据导向的方式确实管理了跨类型运算符的复杂性，但它很笨重。有了这样一个系统，引入一个新类型的代价不只是为那个类型编写方法，还包括构造和安装那些实现跨类型操作的函数。这一负担很容易要求比定义该类型本身的运算所需的代码多得多。

虽然按类型分派和数据导向编程这两种技术确实创建了可增量的泛型函数实现，但它们并没有有效地分离实现关注点；各个数值类型的实现者在编写跨类型操作时，需要考虑其他类型。把有理数与复数结合起来，严格来说并不属于任何一种类型的领域。在设计具有许多类型和跨类型操作的系统时，就类型之间责任划分制定连贯一致的政策，可能是一项极其艰巨的任务。

**类型转换。** 在完全无关的操作作用于完全无关的类型这一普遍情形中，实现显式的跨类型操作尽管可能笨重，却是人们所能期望的最好办法。幸运的是，我们有时可以利用类型系统中潜在的一些额外结构，做得更好。不同的数据类型往往并非完全独立，可能存在某些方式，把一种类型的对象视为另一种类型。这个过程称为*类型转换*（coercion）。例如，如果要求我们把一个有理数与一个复数进行算术组合，我们可以把这个有理数视为一个虚部为零的复数。这样一来，我们就问题转化为组合两个复数的问题，而后者可以用通常的方式由 `add_complex` 和 `mul_complex` 来处理。

一般来说，我们可以通过设计把一种类型的对象转换成另一种类型的等价对象的转换函数来实现这个想法。下面是一个典型的转换函数，它把一个有理数转换为虚部为零的复数：

```python
>>> def rational_to_complex(x):
        return ComplexRI(x.numer/x.denom, 0)
```

现在，我们可以定义一个转换函数的字典。随着引入更多数值类型，这个字典可以被扩展。

```python
>>> coercions = {('rat', 'com'): rational_to_complex}
```

一般来说，并不可能把每种类型的任意数据对象都转换成所有其他类型。例如，没有办法把任意复数转换成有理数，因此 `coercions` 字典中就不会有这种转换实现。

利用 `coercions` 字典，我们可以写一个名为 `coerce_apply` 的函数，它尝试把参数转换成同一类型的值，然后才应用运算符。`coerce_apply` 的实现字典不包含任何跨类型运算符实现。

```python
>>> def coerce_apply(operator_name, x, y):
        tx, ty = type_tag(x), type_tag(y)
        if tx != ty:
            if (tx, ty) in coercions:
                tx, x = ty, coercions[(tx, ty)](x)
            elif (ty, tx) in coercions:
                ty, y = tx, coercions[(ty, tx)](y)
            else:
                return 'No coercion possible.'
        key = (operator_name, tx)
        return coerce_apply_implementations[key](x, y)
```

`coerce_apply` 的 `implementations` 只需要一个类型标签，因为它们假定两个值共享同一个类型标签。因此，我们只需要四个实现就能支持对复数和有理数的泛型算术。

```python
>>> coerce_apply_implementations = {('mul', 'com'): mul_complex,
                                    ('mul', 'rat'): mul_rationals,
                                    ('add', 'com'): add_complex,
                                    ('add', 'rat'): add_rationals}
```

有了这些实现，`coerce_apply` 就可以取代 `apply`。

```python
>>> coerce_apply('add', ComplexRI(1.5, 0), Rational(3, 2))
ComplexRI(3.0, 0)
>>> coerce_apply('mul', Rational(1, 2), ComplexMA(10, 1))
ComplexMA(5.0, 1.0)
```

与定义显式跨类型操作的方法相比，这种转换方案有一些优势。尽管我们仍然需要编写转换函数来关联类型，但我们只需为每一对类型编写一个函数，而不是为每一组类型和每一个泛型操作各编写一个不同的函数。我们在这里所依赖的是这样一个事实：类型之间适当的转换只取决于类型本身，而不取决于所要应用的特定操作。

进一步的优势来自对转换的扩展。一些更复杂的转换方案不只是尝试把一种类型转换成另一种，而可能尝试把两种不同的类型各自转换成第三种共同的类型。考虑一个菱形和一个矩形：它们都不是对方的特例，但两者都可以看作四边形。对转换的另一项扩展是迭代转换，即通过中间类型把一种数据类型转换成另一种。考虑到一个整数可以通过先转换成有理数、再把该有理数转换成实数，从而转换成一个实数。以这种方式把转换串联起来，可以减少程序所需的转换函数总数。

尽管有这些优势，转换确实有潜在的缺点。其一，转换函数在被应用时可能丢失信息。在我们的例子中，有理数是精确表示，但当它们被转换成复数时就变成了近似值。

有些编程语言内置了自动转换系统。事实上，早期版本的 Python 在对象上有一个 `__coerce__` 特殊方法。最终，内置转换系统的复杂性不足以证明其使用的合理性，因此它被移除了。取而代之的是，特定的运算符会按需对其参数应用转换。运算符是通过像 `__add__` 和 `__mul__` 这样的特殊方法，在用户定义类型上以方法调用的方式实现的。至于是采用类型分派、数据导向编程、消息传递还是类型转换来实现程序中的泛型函数，则留给你——用户——来决定。
