## 3.4   具有组合能力的语言的解释器

我们以描述语言的技术展开这一部分的旅程——用其他语言来建立某种语言。*元语言抽象（metalinguistic abstraction）*——即建立新语言——在所有工程设计分支中都扮演着重要角色。它对计算机编程尤为重要，因为在编程中，我们不仅可以构造新的语言，还可以通过构造解释器来实现这些语言。一个编程语言的解释器（interpreter）是一个函数，当它作用于该语言的一个表达式时，会执行求值（evaluation）该表达式所需的各种动作。

我们首先为一个语言定义一个解释器，它是 Scheme 的一个受限子集，称为 Calculator 语言（Calculator）。然后，我们将勾勒出一个针对整个 Scheme 的解释器。我们创建的解释器将是完备的——它允许我们用 Scheme 编写完全通用的程序。为此，它将实现与我们在第 1 章为 Python 程序引入的相同的求值环境模型。

本节中的许多示例都收录于配套的 [Scheme 语法计算器示例](../examples/scalc/scalc.html) 中，因为它们太复杂，无法自然地嵌入本文的格式。

### 3.4.1   一个 Scheme 语法的计算器

Scheme 语法的计算器（Scheme-Syntax Calculator，或简称 Calculator）是一种用于加、减、乘、除算术运算的表达式语言。Calculator 语言与 Scheme 共享调用表达式（call expression）语法和运算符行为。加法（`+`）和乘法（`*`）运算各自接受任意数量的参数：

```scheme
> (+ 1 2 3 4)
10
> (+)
0
> (* 1 2 3 4)
24
> (*)
1
```

减法（`-`）有两种行为。当只有一个参数时，它对该参数取负。当至少有两个参数时，它用第一个参数减去其余所有参数。除法（`/`）也有一对类似的行为：计算单个参数的乘法逆元，或者用第一个参数除以其余所有参数：

```scheme
> (- 10 1 2 3)
4
> (- 3)
-3
> (/ 15 12)
1.25
> (/ 30 5 2)
3
> (/ 10)
0.1
```

调用表达式的求值方式是先求值其操作数子表达式，再将运算符应用于所得的各参数：

```scheme
> (- 100 (* 7 (+ 8 (/ -12 -3))))
16.0
```

我们将用 Python 实现一个 Calculator 语言的解释器。也就是说，我们将编写一个 Python 程序，它以字符串行为输入，并返回将这些行作为 Calculator 表达式求值的结果。如果计算器表达式格式不正确，我们的解释器将引发（raise）一个适当的异常。

### 3.4.2   表达式树

在本课程之前的章节中，表达式树（expression tree）一直是我们在描述求值过程时提及的概念性实体；我们此前从未在程序中把表达式树显式地表示为数据。为了编写一个解释器，我们必须把表达式当作数据来操作。

在 Calculator 中，基本表达式（primitive expression）就是一个数字或一个字符串：要么是 `int` 或 `float`，要么是一个运算符符号。所有组合表达式都是调用表达式。调用表达式是一个 Scheme 列表，其第一个元素（运算符）后面跟着零个或多个操作数表达式。

**Scheme Pairs（点对）。** 在 Scheme 中，列表是嵌套的点对，但并非所有点对都是列表。为了在 Python 中表示 Scheme 的点对和列表，我们将定义一个 `Pair` 类，它与本章前面的 `Rlist` 类类似。其实现出现在 [scheme_reader](../examples/scalc/scheme_reader.py.html) 中。

空列表由一个称为 `nil` 的对象表示，它是类 `nil` 的一个实例。我们假设只会创建一个 `nil` 实例。

`Pair` 类和 `nil` 对象是在 Python 中表示的 Scheme 值。它们的 `repr` 字符串是 Python 表达式，而 `str` 字符串是 Scheme 表达式。

```python
>>> s = Pair(1, Pair(2, nil))
>>> s
Pair(1, Pair(2, nil))
>>> print(s)
(1 2)
```

它们实现了基本的 Python 序列接口——长度和元素选取，以及一个返回 Scheme 列表的 `map` 方法。

```python
>>> len(s)
2
>>> s[1]
2
>>> print(s.map(lambda x: x+4))
(5 6)
```

**树。** 在 Scheme 中，树通过允许 Scheme 列表的元素本身也是 Scheme 列表来表示。嵌套的 Scheme 表达式 `(+ (* 3 4) 5)` 是一棵树，它表示为

```python
>>> exp = Pair('+', Pair(Pair('*', Pair(3, Pair(4, nil))), Pair(5, nil)))
>>> print(exp)
(+ (* 3 4) 5)
>>> print(exp.second.first)
(* 3 4)
>>> exp.second.first.second.first
3
```

与上一章中的 `Tree` 类不同，这些表达式树只在叶子处有值，而且每棵树可以有任意数量的分支。

这个例子表明，所有 Calculator 表达式都是嵌套的 Scheme 列表。我们的 Calculator 解释器将读入嵌套的 Scheme 列表，把它们转换成用嵌套 `Pair` 实例表示的表达式树（参见下文*解析表达式*），然后对表达式树求值以产生值（参见下文*Calculator 求值*）。

### 3.4.3   解析表达式

解析（parsing）是根据原始文本输入生成表达式树的过程。解析器（parser）由两个组件构成：一个词法分析器（lexical analyzer）和一个语法分析器（syntactic analyzer）。首先，*词法分析器（lexical analyzer）*把输入字符串划分成*记号（token）*，记号是语言的最小语法单元，例如名称和符号。其次，*语法分析器（syntactic analyzer）*根据这个记号序列构造出一棵表达式树。词法分析器产生的记号序列由语法分析器消费。

**词法分析（lexical analysis）。** 把字符串解释为记号序列的组件称为*分词器（tokenizer）*或*词法分析器（lexical analyzer）*。在我们的实现中，分词器是 [scheme_tokens](../examples/scalc/scheme_tokens.py.html) 中一个名为 `tokenize_line` 的函数。Scheme 记号由空白、圆括号、点或单引号分隔。分隔符是记号，符号和数字也是。分词器逐字符分析一行，验证符号和数字的格式。

对一个格式良好的 Calculator 表达式进行分词，会分离出所有符号和分隔符，同时识别多字符数字（例如 2.3）并将它们转换成数值类型。

```python
>>> tokenize_line('(+ 1 (* 2.3 45))')
['(', '+', 1, '(', '*', 2.3, 45, ')', ')']
```

词法分析是一个迭代过程，它可以对输入程序的每一行单独应用。

**语法分析（syntactic analysis）。** 把记号序列解释为表达式树的组件称为*语法分析器（syntactic analyzer）*。语法分析是一个树递归（tree-recursive）过程，它必须考虑一个可能跨越多行的完整表达式。

语法分析由 [scheme_reader](../examples/scalc/scheme_reader.py.html) 中的 `scheme_read` 函数实现。它之所以是树递归的，是因为分析一个记号序列常常涉及把其中某个子序列分析成一个子表达式，而这个子表达式本身又充当更大表达式树的一个分支（例如操作数）。递归生成了求值器所消费的层次结构。

`scheme_read` 函数期望其输入 `src` 是一个 `Buffer` 实例，它提供对记号序列的访问。`Buffer` 定义在 [buffer](../examples/scalc/buffer.py.html) 模块中，它把跨越多行的记号收集到一个可以被语法分析的对象中。

```python
>>> lines = ['(+ 1', '   (* 2.3 45))']
>>> expression = scheme_read(Buffer(tokenize_lines(lines)))
>>> expression
Pair('+', Pair(1, Pair(Pair('*', Pair(2.3, Pair(45, nil))), nil)))
>>> print(expression)
(+ 1 (* 2.3 45))
```

`scheme_read` 函数首先检查各种基准情况，包括空输入（这会引发文件结束异常，在 Python 中称为 `EOFError`）和基本表达式。每当一个 `(` 记号指示列表开始时，就会递归调用 `read_tail`。

`read_tail` 函数继续从同一个输入 `src` 读取，但它预期是在一个列表已经开始之后被调用。它的基准情况是空输入（一个错误）或终结该列表的右括号。它的递归调用用 `scheme_read` 读取列表的第一个元素，用 `read_tail` 读取列表的其余部分，然后返回一个以 `Pair` 表示的列表。

`scheme_read` 的这个实现可以读取格式良好的 Scheme 列表，这正是 Calculator 语言所需的全部内容。解析带点的列表（dotted list）和引用形式（quoted form）留作练习。

信息丰富的语法错误会显著提升解释器的可用性。所引发的 `SyntaxError` 异常会包含对所遇到问题的描述。

### 3.4.4   Calculator 求值

[scalc](../examples/scalc/scalc.py.html) 模块实现了 Calculator 语言的求值器（evaluator）。`calc_eval` 函数接受一个表达式作为参数并返回其值。辅助函数 `simplify`、`reduce` 和 `scheme_list` 的定义出现在模型中，并在下文使用。

对于 Calculator 而言，表达式仅有的两种合法语法形式是数字和调用表达式，其中调用表达式是表示格式良好 Scheme 列表的 `Pair` 实例。数字是*自求值（self-evaluating）*的；它们可以直接从 `calc_eval` 返回。调用表达式则需要函数应用。

```python
>>> def calc_eval(exp):
        """Evaluate a Calculator expression."""
        if type(exp) in (int, float):
            return simplify(exp)
        elif isinstance(exp, Pair):
            arguments = exp.second.map(calc_eval)
            return simplify(calc_apply(exp.first, arguments))
        else:
            raise TypeError(exp + ' is not a number or call expression')
```

调用表达式的求值方式是：首先把 `calc_eval` 函数递归地映射到操作数列表上，从而计算出一个 `arguments` 列表。然后，在第二个函数 `calc_apply` 中把运算符应用于这些参数。

Calculator 语言足够简单，我们可以轻松地在单个函数体内表达应用每个运算符的逻辑。在 `calc_apply` 中，每个条件子句对应一个运算符的应用。

```python
>>> def calc_apply(operator, args):
        """Apply the named operator to a list of args."""
        if not isinstance(operator, str):
            raise TypeError(str(operator) + ' is not a symbol')
        if operator == '+':
            return reduce(add, args, 0)
        elif operator == '-':
            if len(args) == 0:
                raise TypeError(operator + ' requires at least 1 argument')
            elif len(args) == 1:
                return -args.first
            else:
                return reduce(sub, args.second, args.first)
        elif operator == '*':
            return reduce(mul, args, 1)
        elif operator == '/':
            if len(args) == 0:
                raise TypeError(operator + ' requires at least 1 argument')
            elif len(args) == 1:
                return 1/args.first
            else:
                return reduce(truediv, args.second, args.first)
        else:
            raise TypeError(operator + ' is an unknown operator')
```

上面，每个语句块计算不同运算符的结果，或者在给出的参数个数不对时引发适当的 `TypeError`。`calc_apply` 函数可以直接应用，但传递给它作为参数的必须是*值*的列表，而不是操作数表达式的列表。

```python
>>> calc_apply('+', scheme_list(1, 2, 3))
6
>>> calc_apply('-', scheme_list(10, 1, 2, 3))
4
>>> calc_apply('*', nil)
1
>>> calc_apply('*', scheme_list(1, 2, 3, 4, 5))
120
>>> calc_apply('/', scheme_list(40, 5))
8.0
```

`calc_eval` 的作用是：先计算操作数子表达式的值，再把它们作为参数传给 `calc_apply`，从而正确调用 `calc_apply`。因此，`calc_eval` 可以接受一个嵌套表达式。

```python
>>> print(exp)
(+ (* 3 4) 5)
>>> calc_eval(exp)
17
```

`calc_eval` 的结构是**按类型分派（dispatching on type）**的一个例子：即根据表达式的形式进行分派。第一种形式的表达式是数字，它不需要额外的求值步骤。一般来说，不需要额外求值步骤的基本表达式称为*自求值（self-evaluating）*的。在我们的 Calculator 语言中，唯一自求值的表达式是数字，但一个通用的编程语言可能还会包含字符串、布尔值等。

**读-求值-打印循环（read-eval-print loops）。** 与解释器交互的一种典型方式是通过读-求值-打印循环（read-eval-print loop, REPL），它是一种交互模式：读取一个表达式、对其求值，并把结果打印给用户。Python 交互式会话就是这种循环的一个例子。

REPL 的实现可以在很大程度上独立于它所使用的解释器。下面的 `read_eval_print_loop` 函数缓冲来自用户的输入，用特定于语言的 `scheme_read` 函数构造一个表达式，然后打印把 `calc_eval` 应用于该表达式的结果。

```python
>>> def read_eval_print_loop():
        """Run a read-eval-print loop for calculator."""
        while True:
            src = buffer_input()
            while src.more_on_line:
                expression = scheme_read(src)
                print(calc_eval(expression))
```

这个版本的 `read_eval_print_loop` 包含了交互式界面的所有必要组件。一个示例会话如下：

```scheme
> (* 1 2 3)
6
> (+)
0
> (+ 2 (/ 4 8))
2.5
> (+ 2 2) (* 3 3)
4
9
> (+ 1
     (- 23)
     (* 4 2.5))
-12
```

这个循环实现没有终止或错误处理的机制。我们可以通过向用户报告错误来改进界面。我们还可以允许用户通过发出键盘中断信号（UNIX 上的 `Control-C`）或文件结束异常（UNIX 上的 `Control-D`）来退出循环。为了实现这些改进，我们把 `while` 语句原本的语句块放进一个 `try` 语句中。第一个 `except` 子句处理 `scheme_read` 引发的 `SyntaxError` 和 `ValueError` 异常，以及 `calc_eval` 引发的 `TypeError` 和 `ZeroDivisionError` 异常。

```python
>>> def read_eval_print_loop():
        """Run a read-eval-print loop for calculator."""
        while True:
            try:
                src = buffer_input()
                while src.more_on_line:
                    expression = scheme_read(src)
                    print(calc_eval(expression))
            except (SyntaxError, TypeError, ValueError, ZeroDivisionError) as err:
                print(type(err).__name__ + ':', err)
            except (KeyboardInterrupt, EOFError):  # <Control>-D, etc.
                print('Calculation completed.')
                return
```

这个循环实现会报告错误而不退出循环。与其在出错时退出程序，不如在给出错误信息后重新启动循环，让用户修改他们的表达式。在导入 `readline` 模块后，用户甚至可以使用上箭头或 `Control-P` 来召回之前的输入。最终结果提供了一个信息丰富的错误报告界面：

```scheme
> )
SyntaxError: unexpected token: )
> 2.3.4
ValueError: invalid numeral: 2.3.4
> +
TypeError: + is not a number or call expression
> (/ 5)
TypeError: / requires exactly 2 arguments
> (/ 1 0)
ZeroDivisionError: division by zero
```

随着我们把解释器推广到 Calculator 之外的新语言，我们将看到 `read_eval_print_loop` 是由一个解析函数、一个求值函数以及 `try` 语句所处理的异常类型来参数化的。除了这些变化之外，所有的 REPL 都可以用相同的结构实现。
