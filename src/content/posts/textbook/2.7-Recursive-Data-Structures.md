## 2.7   递归数据结构

对象可以把其他对象作为属性值。当某个类的对象拥有同一类的属性值时，结果就构成了递归数据结构（recursive data structure）。

### 2.7.1   递归列表类

递归列表（recursive list）在本章前面介绍过，它是由第一个元素和列表的剩余部分组成的抽象数据类型。递归列表的剩余部分本身又是一个递归列表。空列表被当作一种特殊情况处理，它既没有第一个元素，也没有剩余部分。递归列表是一个序列：它长度有限，并支持按索引选取元素。

现在我们可以实现一个具有相同行为的类。在这个版本中，我们将使用特殊方法名来定义它的行为，从而使我们的类可以与 Python 内置的 `len` 函数和元素选择运算符（方括号或 `operator.getitem`）配合工作。这些内置函数会调用类的特殊方法名：长度由 `__len__` 计算，元素选择由 `__getitem__` 计算。

```python
>>> class Rlist:
        """A recursive list consisting of a first element and the rest."""
        class EmptyList(object):
            def __len__(self):
                return 0
        empty = EmptyList()
        def __init__(self, first, rest=empty):
            self.first = first
            self.rest = rest
        def __getitem__(self, i):
            if i == 0:
                return self.first
            else:
                return self.rest[i-1]
        def __len__(self):
            return 1 + len(self.rest)
```

```python
>>> s = Rlist(3, Rlist(4, Rlist(5)))
>>> len(s)
3
>>> s[1]
4
```

`__len__` 和 `__getitem__` 的定义实际上是递归的。当把 Python 内置函数 `len` 应用于用户定义的对象参数时，它会调用一个名为 `__len__` 的方法。同样，元素选择运算符会调用名为 `__getitem__` 的方法。因此，这两个方法的方法体会间接地调用自身。

我们的实现已经完整，但目前很难查看 `Rlist` 类的实例。为了便于调试，我们还可以定义一个函数，把 `Rlist` 转换成字符串表达式。

```python
>>> def rlist_expression(s):
        """Return a string that would evaluate to s."""
        if s.rest is Rlist.empty:
            rest = ''
        else:
            rest = ', ' + rlist_expression(s.rest)
        return 'Rlist({0}{1})'.format(s.first, rest)
```

```python
>>> rlist_expression(s)
'Rlist(3, Rlist(4, Rlist(5)))'
```

这种显示 `Rlist` 的方式非常方便，以至于我们希望只要显示 `Rlist` 实例时就用它。我们可以把 `rlist_expression` 函数设为特殊类属性 `__repr__` 的值，以确保这种行为的出现。Python 通过调用用户定义类实例的 `__repr__` 方法来显示它们。

```python
>>> Rlist.__repr__ = rlist_expression
>>> s
Rlist(3, Rlist(4, Rlist(5)))
```

利用 `Rlist` 类，我们可以定义一些递归列表上的常见操作。例如，我们可以创建一个新的 `Rlist`，它包含两个输入 `Rlist` 的所有元素。

```python
>>> def extend_rlist(s1, s2):
        """Return an Rlist with the elements of s1 followed by those of s2."""
        if s1 is Rlist.empty:
            return s2
        else:
            return Rlist(s1.first, extend_rlist(s1.rest, s2))
```

于是，举例来说，我们可以用 `s` 去扩展 `s` 的剩余部分。

```python
>>> extend_rlist(s.rest, s)
Rlist(4, Rlist(5, Rlist(3, Rlist(4, Rlist(5)))))
```

把一个函数映射到递归列表上的实现具有类似的结构。

```python
>>> def map_rlist(s, fn):
        if s is Rlist.empty:
            return s
        else:
            return Rlist(fn(s.first), map_rlist(s.rest, fn))
```

```python
>>> map_rlist(s, square)
Rlist(9, Rlist(16, Rlist(25)))
```

过滤多了一个条件语句，但也具有类似的递归结构。

```python
>>> def filter_rlist(s, fn):
        if s is Rlist.empty:
            return s
        else:
            rest = filter_rlist(s.rest, fn)
            if fn(s.first):
                return Rlist(s.first, rest)
            else:
                return rest
```

```python
>>> filter_rlist(s, lambda x: x % 2 == 1)
Rlist(3, Rlist(5))
```

列表操作的递归实现通常不需要局部赋值或 `while` 语句。相反，递归列表可以随着函数应用的进行被逐步拆解和构造。

### 2.7.2   层次结构

层次结构源于数据的闭包性质，该性质表明，例如元组可以包含其他元组。举例来说，考虑下面这种 1 到 5 这几个数的嵌套表示。这个元组是一个长度为三的序列，其中前两个元素本身就是元组。包含元组或其他值的元组就是一棵树（tree）。

```python
t = ((1, 2), (3, 4), 5)
```

在树中，每棵子树本身也是一棵树。作为基础情况，任何不是元组的裸元素本身都是一棵简单树，即没有分支的树。也就是说，这些数字都是树，`(1, 2)` 这个对以及整个结构也都是树。

递归是处理树结构的天然工具，因为我们常常可以通过对树的每个分支执行相同的操作来处理整棵树，并且对分支的分支也同样处理，直到到达树的叶子。作为一个例子，我们可以实现一个 `count_leaves` 函数，它返回一棵树中叶子的总数。单步执行这个函数，看看叶子是如何被计数的。

```python
def count_leaves(tree):
    if type(tree) != tuple:
        return 1
    else:
        return sum(map(count_leaves, tree))

t = ((1, 2), (3, 4), 5)
result = count_leaves(t)
```

正如 `map` 是处理序列的强大工具一样，映射与递归结合在一起，为操作树提供了一种强大的通用计算形式。例如，我们可以用一个高阶递归函数 `map_tree` 对一棵树的所有叶子求平方，它的结构与 `count_leaves` 十分相似。

```python
>>> def map_tree(tree, fn):
        """Map fn over all leaves in tree."""
        if type(tree) != tuple:
            return fn(tree)
        else:
            return tuple(map_tree(branch, fn) for branch in tree)
```

```python
>>> t = ((1, 2), (3, 4), 5)
>>> map_tree(t, square)
((1, 4), (9, 16), 25)
```

**内部值。** 上面描述的树只在叶子处有值。树结构数据的另一种常见表示法还会为树的内部节点赋予值。内部的值在树中被称为条目（`entry`）。下面的 `Tree` 类表示这类树，其中每棵树至多有两个分支 `left` 和 `right`。

```python
>>> class Tree:
        def __init__(self, entry, left=None, right=None):
            self.entry = entry
            self.left = left
            self.right = right
        def __repr__(self):
            if self.left or self.right:
                args = self.entry, self.left, self.right
                return 'Tree({0}, {1}, {2})'.format(*args)
            else:
                return 'Tree({0})'.format(self.entry)
```

例如，`Tree` 类可以表示 `fib`（计算斐波那契数的函数）递归实现中算出的那些值所构成的表达式树。下面的函数 `fib_tree(n)` 返回一棵 `Tree`，它的 `entry` 是第 n 个斐波那契数，分支中则保存着此前所有已算出的斐波那契数的轨迹。

```python
>>> def fib_tree(n):
        """Return a Tree that represents a recursive Fibonacci calculation."""
        if n == 1:
            return Tree(0)
        elif n == 2:
            return Tree(1)
        else:
            left = fib_tree(n-2)
            right = fib_tree(n-1)
            return Tree(left.entry + right.entry, left, right)
```

```python
>>> fib_tree(5)
Tree(3, Tree(1, Tree(0), Tree(1)), Tree(2, Tree(1), Tree(1, Tree(0), Tree(1))))
```

以这种方式表示的树同样用递归函数来处理。例如，我们可以求一棵树中所有条目之和。作为基础情况，我们规定空分支没有条目。

```python
>>> def sum_entries(t):
        """Sum the entries of a Tree instance, which may be None."""
        if t is None:
            return 0
        else:
            return t.entry + sum_entries(t.left) + sum_entries(t.right)
```

```python
>>> sum_entries(fib_tree(5))
10
```

### 2.7.3   记忆化

上面的 `fib_tree` 函数可能生成非常大的树。例如，`fib_tree(35)` 由 18,454,929 个 `Tree` 类实例组成。然而，其中许多树在结构上是完全相同的。比如，`left` 子树和 `right` 子树的 `right` 子树都是调用 `fib_tree(33)` 的结果。只创建一棵这样的子树并多次使用它，可以节省大量的时间和内存。

树递归的数据结构和计算过程往往可以通过*记忆化（memoization）*变得更高效，这是一项用于提高重复计算的递归函数效率的强大技术。记忆化的函数会为它此前接收过的任何参数存储返回值。第二次调用 `fib_tree(33)` 不会构建一棵全新的树，而是返回已经构造好的那棵树。在 `fib_tree(35)` 算出的庞大结构中，只有 35 棵唯一的树（每个斐波那契数一棵）。

记忆化可以自然地表示为一个高阶函数，它也可以用作装饰器。下面的定义创建了一个此前计算结果的*缓存（cache）*，以计算出这些结果的参数为索引。使用字典要求被记忆化函数的参数必须是不可变的。

```python
>>> def memo(f):
        """Return a memoized version of single-argument function f."""
        cache = {}
        def memoized(n):
            if n not in cache:
                cache[n] = f(n)
            return cache[n]
        return memoized
```

我们可以把 `memo` 应用于斐波那契数的递归计算。

```python
>>> @memo
    def fib(n):
        if n == 1:
            return 0
        if n == 2:
            return 1
        return fib(n-2) + fib(n-1)
```

```python
>>> fib(35)
5702887
```

我们也可以用 `memo` 来构造斐波那契树，此时重复的子树只会由记忆化版本的 `fib_tree` 创建一次，但会被多次用作不同更大树的分支。

```python
>>> fib_tree = memo(fib_tree)
>>> big_fib_tree = fib_tree(35)
>>> big_fib_tree.entry
5702887
>>> big_fib_tree.left is big_fib_tree.right.right
True
>>> sum_entries = memo(sum_entries)
>>> sum_entries(big_fib_tree)
142587180
```

在这些情况下，记忆化所节省的计算时间和内存相当可观。我们不再创建 18,454,929 个不同的 `Tree` 类实例，而是只创建 35 个。

### 2.7.4   增长阶

前面的例子说明，不同过程在消耗空间和时间等计算资源的速率上可能差别很大。对于某些函数，我们可以精确预测它们所演化出的计算过程所需的步数。例如，考虑下面这个 `count_factors` 函数，它通过尝试用每一个小于或等于输入 `n` 的平方根的整数去除 `n`，来统计能整除输入 `n` 的整数个数。该实现利用了这样一个事实：如果 $k$ 能整除 $n$ 且 $k < \sqrt{n}$ ，那么就存在另一个因子 $j = n / k$，使得 $j > \sqrt{n}$。

```python
from math import sqrt
def count_factors(n):
    sqrt_n = sqrt(n)
    k, factors = 1, 0
    while k < sqrt_n:
        if n % k == 0:
            factors += 2
        k += 1
    if k * k == n:
        factors += 1
    return factors

result = count_factors(576)
```

这个过程中 `while` 语句体执行的总次数是小于 $\sqrt{n}$ 的最大整数。因此，我们可以说这个函数所用的时间——通常记作 $R(n)$——与输入的平方根成正比，我们将其写作 $R(n) = \sqrt{n}$。

对于大多数函数，我们无法精确确定它们所需的步数或迭代次数。描述这种差异的一种便利方式，是使用*增长阶（order of growth）*的概念，从而在输入变大时，对过程所需的资源获得一种粗略的度量。

设 $n$ 是衡量待求解问题规模的参数，设 $R(n)$ 是过程在规模为 $n$ 的问题上所需的资源量。在前面的例子中，我们把 $n$ 取为给定函数所要计算的数字，但还有其他可能。例如，如果我们的目标是计算某个数的平方根的近似值，我们可能把 $n$ 取为所需精度的位数。一般来说，一个问题会有许多性质，针对其中某些性质来分析给定过程是有意义的。同样，$R(n)$ 也可能度量所用的内存量、执行的基本机器操作次数等等。在每次只执行固定数量操作的计算机上，求值一个表达式所需的时间将正比于求值过程中执行的基本机器操作次数。

我们说 $R(n)$ 的增长阶为 $\Theta(f(n))$，写作 $R(n) = \Theta(f(n))$（读作“$f(n)$ 的 theta”），如果存在与 $n$ 无关的正常数 $k_1$ 和 $k_2$，使得

$$
\begin{equation*}
k_1 \cdot f(n) \leq R(n) \leq k_2 \cdot f(n)
\end{equation*}
$$

对任何足够大的 $n$ 都成立。换言之，对于大的 $n$，$R(n)$ 的值被夹在两个都与 $f(n)$ 同比例增长的值之间：

- 一个下界 $k_1 \cdot f(n)$，以及
- 一个上界 $k_2 \cdot f(n)$

例如，计算 $n!$ 所需的步数与输入 $n$ 成正比增长。因此，这个过程所需的步数按 $\Theta(n)$ 增长。我们还看到，递归实现 `fact` 所需的空间按 $\Theta(n)$ 增长。相比之下，迭代实现 `fact_iter` 所需步数相近，但它所需的空间保持不变。在这种情况下，我们说空间按 $\Theta(1)$ 增长。

我们的树递归斐波那契计算 `fib` 的步数随输入 $n$ 呈指数增长。特别地，可以证明第 n 个斐波那契数是下面这个值最接近的整数

$$
\begin{equation*}
\frac{\phi^{n-2}}{\sqrt{5}}
\end{equation*}
$$

其中 $\phi$ 是黄金比例：

$$
\begin{equation*}
\phi = \frac{1 + \sqrt{5}}{2} \approx 1.6180
\end{equation*}
$$

我们还说过，步数与结果值同比例增长，因此树递归过程需要 $\Theta(\phi^n)$ 步，这是一个随 $n$ 指数增长的函数。

增长阶只对过程的行为给出粗略的描述。例如，一个需要 $n^2$ 步的过程、一个需要 $1000 \cdot n^2$ 步的过程以及一个需要 $3 \cdot n^2 + 10 \cdot n + 17$ 步的过程，都具有 $\Theta(n^2)$ 的增长阶。当然，在某些情形下，增长阶分析对于在一个函数的两种可能实现之间做抉择而言过于粗糙。

然而，增长阶可以有效地提示我们：当改变问题规模时，可以预期过程行为如何变化。对于一个 $\Theta(n)$（线性）过程，规模翻倍大致会使所用资源翻倍。对于一个指数过程，问题规模每增加一点，资源消耗就会乘以一个常数因子。下一个例子考察一个增长阶为对数的算法，因此问题规模翻倍只会使资源需求增加一个常量。

**空间。** 要理解函数的空间需求，我们必须大体规定在我们的计算环境模型中，内存是如何被使用、保留和回收的。在求值一个表达式时，我们必须保留所有*活动（active）*环境，以及这些环境引用的所有值和帧。如果一个环境为某个正在求值的表达式提供了求值上下文，那么它就是活动的。

例如，在求值 `fib` 时，解释器按照前面所示的顺序逐个计算每个值，遍历树的结构。为此，在计算的任何时刻，它只需要跟踪树中位于当前节点之上的那些节点。用于求值其余分支的内存可以被回收，因为它们不会影响未来的计算。一般来说，树递归函数所需的空间将正比于树的最大深度。

下图描绘了求值 `fib(3)` 所创建的环境。在对 `fib` 的初始应用求值其返回表达式的过程中，表达式 `fib(n-2)` 被求值，得到值 0。一旦算出这个值，相应的环境帧（以灰色标出）就不再需要了：它不属于任何活动环境。因此，设计良好的解释器可以回收用于存储这个帧的内存。另一方面，如果解释器当前正在求值 `fib(n-1)`，那么由 `fib` 的这次应用创建的环境（其中 `n` 为 2）是活动的。相应地，最初为把 `fib` 应用于 3 而创建的环境也是活动的，因为它的返回值尚未算出。

```python
def fib(n):
    if n == 1:
        return 0
    if n == 2:
        return 1
    return fib(n-2) + fib(n-1)

result = fib(3)
```

在 `memo` 的情形中，只要活动环境中有某个名字绑定到它所返回的函数，与该函数相关联的环境（其中包含 `cache`）就必须保留。`cache` 字典中的条目数随传给 `fib` 的不同参数个数线性增长，而后者又随输入线性增长。另一方面，迭代实现只需在计算过程中跟踪两个数：`prev` 和 `curr`，因此其规模是常量。

记忆化体现了一个常见的编程模式：计算时间常常可以通过增加空间占用而减少，反之亦然。

### 2.7.5   示例：求幂

考虑计算给定数的幂的问题。我们希望有一个函数，它以底数 `b` 和正整数指数 `n` 为参数，计算 $b^n$。一种做法是通过递归定义

$$
\begin{align*}
b^n &= b \cdot b^{n-1} \\
b^0 &= 1
\end{align*}
$$

这很容易翻译成递归函数

```python
>>> def exp(b, n):
        if n == 0:
            return 1
        return b * exp(b, n-1)
```

这是一个线性递归过程，需要 $\Theta(n)$ 步和 $\Theta(n)$ 空间。与阶乘一样，我们可以很容易地写出等价的线性迭代，它所需步数相近，但空间为常量。

```python
>>> def exp_iter(b, n):
        result = 1
        for _ in range(n):
            result = result * b
        return result
```

我们可以用连续平方来减少求幂所需的步数。例如，不是把 $b^8$ 计算为

$$
\begin{equation*}
b \cdot (b \cdot (b \cdot (b \cdot (b \cdot (b \cdot (b \cdot b))))))
\end{equation*}
$$

而是用三次乘法来计算它：

$$
\begin{align*}
b^2 &= b \cdot b \\
b^4 &= b^2 \cdot b^2 \\
b^8 &= b^4 \cdot b^4
\end{align*}
$$

这种方法对 2 的幂次指数很有效。如果使用递归规则，我们也可以在一般情形下利用连续平方来计算幂

$$
\begin{equation*}
b^n = \begin{cases} (b^{\frac{1}{2} n})^2 & \text{if $n$ is even} \\
 b \cdot b^{n-1} & \text{if $n$ is odd}
 \end{cases}
\end{equation*}
$$

我们也可以把这种方法表示为递归函数：

```python
>>> def square(x):
        return x*x
```

```python
>>> def fast_exp(b, n):
        if n == 0:
            return 1
        if n % 2 == 0:
            return square(fast_exp(b, n//2))
        else:
            return b * fast_exp(b, n-1)
```

```python
>>> fast_exp(2, 100)
1267650600228229401496703205376
```

`fast_exp` 所演化的过程在空间和步数上都随 `n` 对数增长。要看出这一点，注意用 `fast_exp` 计算 $b^{2n}$ 只比计算 $b^n$ 多一次乘法。因此，我们所能计算的指数规模（近似地）随允许我们进行的每一次新乘法而翻倍。于是，指数为 `n` 时所需的乘法次数大致按以 2 为底的 `n` 的对数增长。该过程具有 $\Theta(\log n)$ 增长阶。随着 $n$ 变大，$\Theta(\log n)$ 增长与 $\Theta(n)$ 增长之间的差别变得十分显著。例如，`n` 为 1000 时 `fast_exp` 只需要 14 次乘法，而不是 1000 次。

### 2.7.6   集合

除了列表、元组和字典之外，Python 还有第四种内置容器类型，称为集合（`set`）。集合字面量遵循数学记法，元素用花括号括起来。构造时会去除重复元素。集合是无序的集合体，因此打印出来的顺序可能与集合字面量中的元素顺序不同。

```python
>>> s = {3, 2, 1, 4, 4}
>>> s
{1, 2, 3, 4}
```

Python 的集合支持多种操作，包括成员测试、长度计算，以及并集和交集这些标准集合运算

```python
>>> 3 in s
True
>>> len(s)
4
>>> s.union({1, 5})
{1, 2, 3, 4, 5}
>>> s.intersection({6, 5, 4, 3})
{3, 4}
```

除了 `union` 和 `intersection` 之外，Python 的集合还支持若干其他方法。谓词 `isdisjoint`、`issubset` 和 `issuperset` 提供集合比较。集合是可变的，可以用 `add`、`remove`、`discard` 和 `pop` 一次改动一个元素。还有一些方法提供多元素改动，例如 `clear` 和 `update`。Python 的[集合文档](http://docs.python.org/py3k/library/stdtypes.html#set)在课程的这一阶段应该已经足够易懂，可以从中了解细节。

**实现集合。** 从抽象的角度看，集合是一些互异对象的集合体，它支持成员测试、并集、交集和添加（adjunction）。把一个元素和一个集合相加，会返回一个新集合，它包含原集合的所有元素以及这个新元素（如果它与原有元素互异）。并集和交集分别返回出现在两个集合中任一个或两者中的元素所构成的集合。与任何数据抽象一样，只要某种集合表示法提供了这一组行为，我们就可以自由地在它之上实现任何函数。

在本节的剩余部分，我们考虑三种不同的集合实现方式，它们在表示法上各不相同。我们将通过分析集合操作的增长率来刻画这些不同表示法的效率。我们将使用本节前面介绍的 `Rlist` 和 `Tree` 类，它们为基本集合操作提供了简单而优雅的递归解法。

**以无序序列表示集合。** 表示集合的一种方式是使用一个序列，其中任何元素都不出现一次以上。空集用空序列表示。成员测试递归地遍历这个列表。

```python
>>> def empty(s):
        return s is Rlist.empty
```

```python
>>> def set_contains(s, v):
        """Return True if and only if set s contains v."""
        if empty(s):
            return False
        elif s.first == v:
            return True
        else:
            return set_contains(s.rest, v)
```

```python
>>> s = Rlist(3, Rlist(4, Rlist(5)))
>>> set_contains(s, 2)
False
>>> set_contains(s, 5)
True
```

这个 `set_contains` 实现需要 $\Theta(n)$ 时间来测试某个元素是否属于集合，其中 $n$ 是集合 `s` 的大小。利用这个线性时间的成员测试函数，我们也可以在线性时间内向集合中添加一个元素。

```python
>>> def adjoin_set(s, v):
        """Return a set containing all elements of s and element v."""
        if set_contains(s, v):
            return s
        else:
            return Rlist(v, s)
```

```python
>>> t = adjoin_set(s, 2)
>>> t
Rlist(2, Rlist(3, Rlist(4, Rlist(5))))
```

在设计一种表示法时，我们应当关心的一个问题就是效率。求两个集合 `set1` 和 `set2` 的交集同样需要成员测试，但这一次 `set1` 的每个元素都必须在 `set2` 中测试是否属于它，对于两个大小为 $n$ 的集合，这导致步数达到平方级的增长阶 $\Theta(n^2)$。

```python
>>> def intersect_set(set1, set2):
        """Return a set containing all elements common to set1 and set2."""
        return filter_rlist(set1, lambda v: set_contains(set2, v))
```

```python
>>> intersect_set(t, map_rlist(s, square))
Rlist(4)
```

在计算两个集合的并集时，我们必须小心不要让任何元素出现两次。`union_set` 函数同样需要线性次数的成员测试，从而产生一个同样包含 $\Theta(n^2)$ 步的过程。

```python
>>> def union_set(set1, set2):
        """Return a set containing all elements either in set1 or set2."""
        set1_not_set2 = filter_rlist(set1, lambda v: not set_contains(set2, v))
        return extend_rlist(set1_not_set2, set2)
```

```python
>>> union_set(t, s)
Rlist(2, Rlist(3, Rlist(4, Rlist(5))))
```

**以有序元组表示集合。** 加快集合操作的一种方式是改变表示法，使集合元素按递增顺序排列。要做到这一点，我们需要某种比较两个对象以判断谁更大的方法。在 Python 中，许多不同类型的对象都可以用 `<` 和 `>` 运算符比较，但在本例中我们只关注数字。我们将通过把元素按递增顺序列出，来表示一个数字集合。

有序的一个好处体现在 `set_contains` 中：在检查某个对象是否存在时，我们不再需要扫描整个集合。如果我们遇到的集合元素比我们要找的项大，那么我们就知道该项不在集合中：

```python
>>> def set_contains(s, v):
        if empty(s) or s.first > v:
            return False
        elif s.first == v:
            return True
        else:
            return set_contains(s.rest, v)
```

```python
>>> set_contains(s, 0)
False
```

这节省了多少步？在最坏情况下，我们要找的项可能是集合中最大的那个，于是步数与无序表示法相同。另一方面，如果我们查找的项大小各异，那么可以预期有时能在列表靠近开头的地方停止搜索，而其他时候仍需要检查列表的大部分。平均而言，我们应当预期需要检查集合中大约一半的项。因此，平均所需的步数约为 $\frac{n}{2}$。这仍然是 $\Theta(n)$ 增长，但相比之前的实现，它平均节省了 2 倍步数。

通过重新实现 `intersect_set`，我们可以获得更可观的加速。在无序表示法中，该操作需要 $\Theta(n^2)$ 步，因为我们对 `set1` 的每个元素都完整扫描了 `set2`。但有了有序表示法，我们就可以使用更巧妙的方法。我们同时遍历两个集合，跟踪 `set1` 中的元素 `e1` 和 `set2` 中的元素 `e2`。当 `e1` 和 `e2` 相等时，我们把该元素纳入交集。

然而，假设 `e1` 小于 `e2`。由于 `e2` 比 `set2` 中剩余的元素都小，我们可以立即断定 `e1` 不可能出现在 `set2` 的剩余部分中，因此不在交集中。于是，我们不再需要考虑 `e1`；我们丢弃它，继续处理 `set1` 的下一个元素。当 `e2 < e1` 时，类似的逻辑推进 `set2` 的元素。下面是这个函数：

```python
>>> def intersect_set(set1, set2):
        if empty(set1) or empty(set2):
            return Rlist.empty
        else:
            e1, e2 = set1.first, set2.first
            if e1 == e2:
                return Rlist(e1, intersect_set(set1.rest, set2.rest))
            elif e1 < e2:
                return intersect_set(set1.rest, set2)
            elif e2 < e1:
                return intersect_set(set1, set2.rest)
```

```python
>>> intersect_set(s, s.rest)
Rlist(2, Rlist(3))
```

要估计这个过程所需的步数，注意每一步我们都会缩小至少一个集合的规模。因此，所需的步数至多是 `set1` 与 `set2` 大小之和，而不是像无序表示法那样是大小之积。这是 $\Theta(n)$ 增长而非 $\Theta(n^2)$——即使对于中等大小的集合，这也是相当可观的加速。例如，两个大小为 100 的集合求交需要大约 200 步，而不是无序表示法的 10,000 步。

对于以有序序列表示的集合，添加和并集也可以在线性时间内计算。这些实现留作练习。

**以二叉搜索树表示集合。** 通过把集合元素组织成树的形状，我们可以比有序列表表示法做得更好。我们使用前面介绍的 `Tree` 类。树根节点的 `entry` 保存集合中的一个元素。`left` 分支中的条目包括所有小于根节点元素的元素。`right` 分支中的条目包括所有大于根节点元素的元素。下图展示了一些表示集合 `{1, 3, 5, 7, 9, 11}` 的树。同一个集合可以用许多不同的树来表示。对于一种有效的表示法，我们唯一的要求是 `left` 子树中的所有元素都小于树的 `entry`，而 `right` 子树中的所有元素都更大。

![figure](../img/set_trees.png)

树表示法的优势在于：假设我们想检查某个值 `v` 是否包含在集合中。我们先拿 `v` 与 `entry` 比较。如果 `v` 小于它，我们就知道只需搜索 `left` 子树；如果 `v` 更大，我们就只需搜索 `right` 子树。现在，如果树是“平衡的”，那么这两棵子树的大小都约为原来的一半。于是，一步之内我们就把搜索一棵大小为 $n$ 的树的问题化归为搜索一棵大小为 $\frac{n}{2}$ 的树。由于每一步树的规模都减半，我们应当预期搜索一棵树所需的步数按 *Theta(log n)* 增长。对于大的集合，这相比前面的表示法将是显著的加速。下面这个 `set_contains` 函数利用了这种树结构集合的有序性。

```python
>>> def set_contains(s, v):
        if s is None:
            return False
        elif s.entry == v:
            return True
        elif s.entry < v:
            return set_contains(s.right, v)
        elif s.entry > v:
            return set_contains(s.left, v)
```

向集合中添加一个项的实现在方式上类似，同样需要 $\Theta(\log n)$ 步。要添加一个值 `v`，我们把 `v` 与 `entry` 比较，以确定应当把 `v` 加到 `right` 分支还是 `left` 分支，把 `v` 添加到合适的分支后，我们把这个新构造的分支与原来的 `entry` 以及另一个分支拼接起来。如果 `v` 等于 `entry`，我们直接返回该节点。如果要求我们把 `v` 添加到一个空树中，我们就生成一棵以 `v` 为 `entry`、`right` 和 `left` 分支均为空的 `Tree`。下面是这个函数：

```python
>>> def adjoin_set(s, v):
        if s is None:
            return Tree(v)
        elif s.entry == v:
            return s
        elif s.entry < v:
            return Tree(s.entry, s.left, adjoin_set(s.right, v))
        elif s.entry > v:
            return Tree(s.entry, adjoin_set(s.left, v), s.right)
```

```python
>>> adjoin_set(adjoin_set(adjoin_set(None, 2), 3), 1)
Tree(2, Tree(1), Tree(3))
```

我们关于可以在对数步数内完成树搜索的说法，建立在树是“平衡的”这一假设之上，即每棵树的左子树和右子树所具有的元素个数大致相同，从而每棵子树包含其父节点大约一半的元素。但是，我们如何能确定自己所构造的树会是平衡的？即使我们从一棵平衡树开始，用 `adjoin_set` 添加元素也可能产生不平衡的结果。由于新添加元素的位置取决于该元素与集合中已有项的比较结果，我们可以预期，如果“随机地”添加元素，树在平均意义上往往会趋于平衡。

但这并非保证。例如，如果我们从空集开始，依次添加数字 1 到 7，最终会得到一棵高度不平衡的树，其中所有左子树都是空的，因此它相比一个简单的有序列表没有任何优势。解决这个问题的一种方式是定义一个操作，把任意一棵树转换成具有相同元素的平衡树。我们可以在每进行若干次 `adjoin_set` 操作后执行这一转换，使我们的集合保持平衡。

交集和并集操作可以通过把树结构集合转换为有序列表再转换回来，在线性时间内完成。细节留作练习。

**Python 的集合实现。** Python 内置的 `set` 类型在内部并不使用上述任何一种表示法。相反，Python 使用一种基于称为*哈希（hashing）*的技术的表示法，它提供常量时间的成员测试和添加操作，哈希是另一门课程的主题。内置的 Python 集合不能包含可变数据类型，例如列表、字典或其他集合。为了允许嵌套集合，Python 还包含一个内置的不可变 `frozenset` 类，它与 `set` 类共享方法，但不包含改动方法和运算符。
