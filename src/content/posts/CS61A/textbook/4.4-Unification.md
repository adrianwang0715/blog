## 4.4   合一

本节描述查询解释器的一个实现，它在 `logic` 语言中执行推理。该解释器是一个通用的求解器，但在它能求解的问题的规模和类型上有很大的局限。虽然存在更完善的逻辑编程语言，但高效推理过程的构造至今仍是计算机科学中活跃的研究课题。

查询解释器所执行的基本操作称为*合一（unification）*。合一是一种通用的方法，用于把查询与事实匹配起来，而查询和事实都可能含有变量。查询解释器反复应用这一操作：首先把原始查询与各个事实的结论相匹配，然后再把各事实的假设与数据库中的其他结论相匹配。在此过程中，查询解释器在与某个查询相关的所有事实构成的空间中进行搜索。如果它能找到一种变量赋值方式来支持该查询，就将该赋值作为成功的结果返回。

### 4.4.1   模式匹配

为了返回与查询匹配的简单事实，解释器必须把一个含有变量的查询与一个不含变量的事实匹配起来。例如，查询 `(query (parent abraham ?child))` 与事实 `(fact (parent abraham barack))` 相匹配，只要变量 `?child` 取值 `barack`。

一般地，如果存在一种变量名到值的绑定（binding），使得把这些值代入模式（pattern）后得到该表达式，那么这个模式就匹配某个表达式（一个可能嵌套的 Scheme 列表）。

例如，表达式 `((a b) c (a b))` 与模式 `(?x c ?x)` 相匹配，其中变量 `?x` 绑定到值 `(a b)`。同一个表达式也与模式 `((a ?y) ?z (a b))` 相匹配，其中变量 `?y` 绑定到 `b`，`?z` 绑定到 `c`。

### 4.4.2   表示事实与查询

下面的例子可以通过导入所提供的 [logic](http://composingprograms.com/examples/logic/logic.py.html) 示例程序来复现。

```python
>>> from logic import *
```

在 logic 语言中，查询和事实都表示为 Scheme 列表，使用与上一章相同的 `Pair` 类和 `nil` 对象。例如，查询表达式 `(?x c ?x)` 表示为嵌套的 `Pair` 实例。

```python
>>> read_line("(?x c ?x)")
Pair('?x', Pair('c', Pair('?x', nil)))
```

与 Scheme 项目中一样，一个把符号绑定到值的环境用 `Frame` 类的实例来表示，它有一个名为 `bindings` 的属性。

在 `logic` 语言中执行模式匹配的函数称为 `unify`。它接受两个输入 `e` 和 `f`，以及一个记录变量到值绑定的环境 `env`。

```python
>>> e = read_line("((a b) c (a b))")
>>> f = read_line("(?x c ?x)")
>>> env = Frame(None)
>>> unify(e, f, env)
True
>>> env.bindings
{'?x': Pair('a', Pair('b', nil))}
>>> print(env.lookup('?x'))
(a b)
```

上面 `unify` 返回 `True`，表示模式 `f` 能够匹配表达式 `e`。合一的结果记录在 `env` 中，即把 `?x` 绑定到 `(a b)`。

### 4.4.3   合一算法

合一是模式匹配的推广，它试图在两个可能都含有变量的表达式之间找到一种映射。`unify` 函数通过一个递归过程实现合一：它在两个表达式的对应部分上执行合一，直到遇到矛盾，或者能够为所有变量建立起一个可行的绑定。

让我们从一个例子开始。模式 `(?x ?x)` 可以匹配模式 `((a ?y c) (a b ?z))`，因为存在一个不含变量的表达式同时匹配两者：`((a b c) (a b c))`。合一通过以下步骤找出这个解：

1. 为匹配每个模式的第一个元素，变量 `?x` 被绑定到表达式 `(a ?y c)`。
2. 为匹配每个模式的第二个元素，首先把变量 `?x` 替换为其值。然后，通过把 `?y` 绑定到 `b`、把 `?z` 绑定到 `c`，使 `(a ?y c)` 与 `(a b ?z)` 相匹配。

结果，放入传给 `unify` 的环境中的绑定就包含了 `?x`、`?y` 和 `?z` 的条目：

```python
>>> e = read_line("(?x ?x)")
>>> f = read_line(" ((a ?y c) (a b ?z))")
>>> env = Frame(None)
>>> unify(e, f, env)
True
>>> env.bindings
{'?z': 'c', '?y': 'b', '?x': Pair('a', Pair('?y', Pair('c', nil)))}
```

合一的结果可能会把变量绑定到一个同样含有变量的表达式上，正如我们在上面看到的 `?x` 被绑定到 `(a ?y c)`。`bind` 函数会在一个表达式中递归地、反复地把所有变量绑定到它们的值，直到不再有被绑定的变量为止。

```python
>>> print(bind(e, env))
((a b c) (a b c))
```

一般而言，合一通过检查若干条件来进行。`unify` 的实现直接对应于下面的描述。

1. 如果输入 `e` 和 `f` 是变量，则二者都被替换为其值。
2. 如果 `e` 和 `f` 相等，则合一成功。
3. 如果 `e` 是变量，则合一成功，并把 `e` 绑定到 `f`。
4. 如果 `f` 是变量，则合一成功，并把 `f` 绑定到 `e`。
5. 如果二者都不是变量，二者都不是列表，且它们不相等，那么 `e` 和 `f` 无法合一，因此合一失败。
6. 如果上述情况都不成立，那么 `e` 和 `f` 都是序对（pair），因此对它们各自的第一个和第二个对应元素执行合一。

```python
>>> def unify(e, f, env):
        """Destructively extend ENV so as to unify (make equal) e and f, returning
        True if this succeeds and False otherwise.  ENV may be modified in either
        case (its existing bindings are never changed)."""
        e = lookup(e, env)
        f = lookup(f, env)
        if e == f:
            return True
        elif isvar(e):
            env.define(e, f)
            return True
        elif isvar(f):
            env.define(f, e)
            return True
        elif scheme_atomp(e) or scheme_atomp(f):
            return False
        else:
            return unify(e.first, f.first, env) and unify(e.second, f.second, env)
```

### 4.4.4   证明

理解 `logic` 语言的一种方式是把它看作形式系统中断言（assertion）的证明器。每个陈述的事实都在形式系统中确立一条公理，而每个查询都必须由查询解释器从这些公理出发加以确立。也就是说，每个查询都断言：存在某种对其变量的赋值，使得它的所有子表达式同时由系统的各个事实推导出来。查询解释器的职责就是验证这一点确实成立。

例如，给定关于狗的各个事实，我们可以断言 Clinton 和某只棕色的狗有某个共同的祖先。只有当查询解释器能够确立这一断言为真时，它才会输出 `Success!`。作为附带的结果，它还会告知我们那位共同祖先以及那只棕色狗的名字：

```scheme
logic> (query (ancestor ?a clinton)
              (ancestor ?a ?brown-dog)
              (dog (name ?brown-dog) (color brown)))
Success!
a: fillmore   brown-dog: herbert
a: eisenhower brown-dog: fillmore
a: eisenhower brown-dog: herbert
```

结果中显示的三种赋值中的每一种，都是对"在给定事实下该查询为真"这一更大证明的追踪。一个完整的证明会包含所用到的全部事实，例如 `(parent abraham clinton)` 和 `(parent fillmore abraham)`。

### 4.4.5   搜索

为了从系统中已经确立的事实出发确立一个查询，查询解释器在所有可能事实构成的空间中进行搜索。合一是把两个表达式做模式匹配的原语操作。查询解释器中的*搜索过程（search procedure）*负责选择要合一哪些表达式，以找到一组能相互链接、从而确立该查询的事实。

递归的 `search` 函数实现了 `logic` 语言的搜索过程。它以查询中的 `clauses`（子句）这一 Scheme 列表、一个包含符号到值当前绑定（初始为空）的环境 `env`，以及已经链接起来的规则链的 `depth`（深度）为输入。

```python
>>> def search(clauses, env, depth):
        """Search for an application of rules to establish all the CLAUSES,
        non-destructively extending the unifier ENV.  Limit the search to
        the nested application of DEPTH rules."""
        if clauses is nil:
            yield env
        elif DEPTH_LIMIT is None or depth <= DEPTH_LIMIT:
            for fact in facts:
                fact = rename_variables(fact, get_unique_id())
                env_head = Frame(env)
                if unify(fact.first, clauses.first, env_head):
                    for env_rule in search(fact.second, env_head, depth+1):
                        for result in search(clauses.second, env_rule, depth+1):
                            yield result
```

同时满足所有子句的搜索从第一个子句开始。对于数据库中的每个事实，`search` 尝试把该事实的第一个子句与查询的第一个子句合一。合一在一个新的环境 `env_head` 中进行。作为合一的副作用，变量会被绑定到 `env_head` 中的值。

如果合一成功，那么该子句就匹配当前规则的结论。随后的 `for` 语句尝试确立该规则的各个假设，以便结论得以确立。正是在这里，递归规则的假设会被递归地传给 `search` 以求确立。

最后，对于 `fact.second` 的每一次成功搜索，得到的环境都会绑定到 `env_rule`。给定这些值到变量的绑定，最后的 `for` 语句通过搜索来确立初始查询中余下的子句。任何成功的结果都通过内层的 `yield` 语句返回。

**唯一名称。** 合一假定 `e` 和 `f` 之间不共享任何变量。然而，在 `logic` 语言的事实和查询中，我们经常重复使用变量名。我们不希望把一个事实中的 `?x` 与另一个事实中的 `?x` 混淆；这些变量是互不相关的。为确保名称不被混淆，在事实被传进 unify 之前，会用 `rename_variables` 把它的变量名替换为唯一名称，方法是为该事实附加一个唯一的整数。

```python
>>> def rename_variables(expr, n):
        """Rename all variables in EXPR with an identifier N."""
        if isvar(expr):
            return expr + '_' + str(n)
        elif scheme_pairp(expr):
            return Pair(rename_variables(expr.first, n),
                        rename_variables(expr.second, n))
        else:
            return expr
```
