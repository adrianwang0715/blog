# 第 3 章：解释计算机程序

## 3.1   引言

第 1 章和第 2 章描述了编程中两个基本要素之间的紧密联系：函数与数据。我们看到了如何利用高阶函数把函数当作数据来操作。我们也看到了如何通过消息传递和对象系统让数据具有行为。我们还研究了组织大型程序的技术，例如函数抽象、数据抽象、类继承和泛型函数。这些核心概念构成了坚实的基础，使我们能够构建模块化、可维护且可扩展的程序。

本章聚焦于编程的第三个基本要素：程序本身。一个 Python 程序不过是一段文本的集合。只有通过解释（interpretation）的过程，我们才能基于这段文本执行任何有意义的计算。像 Python 这样的编程语言之所以有用，是因为我们可以定义一个*解释器（interpreter）*——一个执行 Python 求值与执行过程的程序。可以毫不夸张地说，这是编程中最根本的思想：决定一门编程语言中表达式含义的解释器，本身不过是一个程序。

理解这一点，就意味着改变我们对自身作为程序员的想象。我们开始把自己看作语言的设计者，而不仅仅是他人所设计语言的使用者。

### 3.1.1   编程语言

各种编程语言在句法结构、特性和应用领域上差异极大。在通用编程语言中，函数定义和函数应用这两种构造形式随处可见。另一方面，也存在一些强大的语言，它们并不包含对象系统、高阶函数、赋值，甚至不包含 `while` 和 `for` 语句这样的控制构造。作为一门特性极简却功能强大的语言的例子，我们将介绍 [Scheme](http://http://en.wikipedia.org/wiki/Scheme_(programming_language)) 编程语言。本书介绍的 Scheme 子集完全不允许可变的值。

在本章中，我们研究解释器的设计，以及它们在执行程序时所创建的计算过程。为一门通用编程语言设计解释器，这件事乍看之下似乎令人生畏。毕竟，解释器是能够根据输入执行任何可能计算的程序。然而，许多解释器都具有一种优雅的共同结构：两个相互递归的函数。第一个函数在环境中对表达式求值；第二个函数把函数应用于参数。

这两个函数之所以是递归的，是因为它们相互定义彼此：应用一个函数需要对其函数体中的表达式求值，而对一个表达式求值又可能涉及一个或多个函数的应用。
